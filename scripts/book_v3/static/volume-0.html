卷 0 · 形式逻辑 · 试写导论

先有“证明是一个项”

这一卷不讲集合论，也不讲实数；只回答一个更基础的问题：在形式化证明里，命题、类型、函数和集合到底是什么关系。读完这一卷，卷 I 的第一句话才不会像是凭空出现的。

1. 命题是类型

在 Lean 里，命题不是一段中文说明，而是类型世界里的一个对象。所有命题都住在 Prop 里；Prop 自己又是 Sort 0。写下一句断言，本质上是在写一个类型。

axiom True : Prop
axiom True.intro : True
axiom False : Prop
axiom False.rec : (P : Prop) → False → P

这里 True 是一个命题；True.intro 是一个类型为 True 的项。所谓“证明一个命题”，就是构造一个类型等于该命题的项。

2. 证明是项

证明不是一段“因为所以”的文字，而是一个值：如果 P : Prop，那么 h : P 就是 P 的一个证明。两个证明可以用函数组合起来；一条蕴含 P → Q 本身就是一个“吃 P 的证明、吐出 Q 的证明”的函数。

theorem and_swap (a b : Prop) (h : a ∧ b) : b ∧ a :=
  And.intro (And.right h) (And.left h)

这段代码对应的自然语言是：假设 a 与 b 都成立，那么把它们交换顺序后仍然都成立。代码里没有“因为所以”，但每一层 fun、每一个构造子，都在做同一件事。

3. 类型也是项，函数是箭头

Nat : Type；Nat → Nat 也是一个类型，它住在 Type 0 = Sort 1。类型和值不是两个世界：类型是更大的类型里的项，箭头是函数类型的写法。

“集合”在这个语言里不是另起一套原始对象。一个集合 A 是某个类型 α 上的谓词：给每个 x : α，回答它是否属于 A。也就是说：

def Set (α : Type) : Type := α → Prop

-- x ∈ A 就是 A x
#check (fun (α : Type) (A : Set α) (x : α) => A x)

所以卷 I 开头说的“集合是谓词”，不是比喻：Set α 展开后就是 α → Prop。形式化证明里，x ∈ A 最终要落到“A x 这个命题有一个证明”上。

4. 这一卷接下来要补什么

这篇只是导论。后面按顺序补：命题联结词与证明项、等式与替换、函数与箭头、量词、归纳与递归、关系与商。补完这些，再进入卷 I 的集合语言，读者就不会只看到一串代码。

另外，正文会遵守一条规矩：先用自然语言说清“在说什么、为什么下一步可以这样走”，紧跟着给对应代码；代码不是正文的替代品，而是它的形式化对照。
