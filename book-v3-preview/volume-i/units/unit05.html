5.0 序对是什么：lib/Prod 已经给好

inductive Prod (A B : Type) -- 类型：A × B ctor prod_mk (a : A) (b : B) : Prod A B -- 构造子：(a, b) def Prod.fst (A B : Type) (p : Prod A B) : A def Prod.snd (A B : Type) (p : Prod A B) : B

构造子叫 prod_mk 而不是 mk：本语言没有命名空间（台账 G-02），构造子是裸名、且全项目唯一；官方 Lean 4 / Mathlib 里它叫 Prod.mk。序对的全部信息就是这两个投影——所以"两个序对相等"这件事，只能靠投影来拆。

练习 3（L 类）：配对定理 —— 序对相等沿两个投影各搬一次。

theorem prod_mk_inj (A B : Type) (a a1 : A) (b b1 : B) :
    @prod_mk A B a b = @prod_mk A B a1 b1 → a = a1 ∧ b = b1 := by
  intro h
  constructor
  exact @Eq.subst.{1} (Prod A B) (fun (p : Prod A B) => a = Prod.fst A B p)
    (@prod_mk A B a b) (@prod_mk A B a1 b1) h (@Eq.refl.{1} A a)

theorem prod_mk_eq_iff (A B : Type) (a a1 : A) (b b1 : B) :
    (@prod_mk A B a b = @prod_mk A B a1 b1) ↔ (a = a1 ∧ b = b1) := by
  constructor
  exact prod_mk_inj A B a a1 b b1
  intro h
  have ha : a = a1 := And.left h
  have hb : b = b1 := And.right h

    (@Eq.subst.{1} A (fun (x : A) => @prod_mk A B a b = @prod_mk A B x b) a a1 ha

5.3 D 类：A × B = B × A 吗？

练习 6prod_set_swap_ne定理附录解答

先看"等式"本身：s ×ˢ t : Set (Prod A B)，而 t ×ˢ s : Set (Prod B A)。两个类型不同 —— 只要 A 与 B 不是同一个类型，"A × B = B × A" 这句话根本写不出来；换成数学语言：需要先有一个 A × B 到 B × A 的交换双射

fun (p : Prod A B) => prod_mk B A (Prod.snd A B p) (Prod.fst A B p)

（双射的正式定义在单元⑦ 与 ⑨；这里只点名，不证。）

退化情形（这时它才成立）：

  • A 与 B 取成同一个类型、并且 s = t：两侧是同一个表达式，等式自明；
  • s 或 t 是空集：两侧都是空集（用上面那个交换映射 + 空集成员刻画说明，本单元不证）。

但即使把类型取成同一个，s ≠ t 时两侧一般也不相等 —— 底下的原因是序对连交换都做不到：只有 a = b 时 prod_mk A A a b 与 prod_mk A A b a 才是同一个序对。下面的练习把这个反例证出来。（设计判断：有序对与 Kuratowski 编码没有实证研究支撑，此处不作"研究表明"的断言。）

练习 6（D 类）：判断 A × B = B × A 并给出反例。

theorem prod_set_swap_ne (A : Type) (a b : A) (h : a ≠ b) :
    {a} ×ˢ {b} ≠ {b} ×ˢ {a} := by

练习 7kura_degenerate定理附录解答

不用原语也能把有序对做成集合，定义是

(a, b) := {{a}, {a, b}}

写成我们的语言（集合字面量）就是 {{a}, {a, b}} -- : Set (Set α) 读法：两层。第一层 {a} 单独把第一个坐标记下来，第二层 {a, b} 把两个坐标都带上；由于 {a} 与 {a, b} 一般不相等，"谁在前"就能从集合里读回来。

问：这样的编码要"够用"，哪条性质是必须的？答：配对映射的单射性 —— 编码必须把"不同的坐标组合"送到不同的集合，否则 (a,b) = (a',b') 推不出 a = a' ∧ b = b'，序对就丢信息了。我们原语版本的这条性质正是 5.1 的 prod_mk_inj；Kuratowski 编码要证的是 {{a},{a,b}} = {{a'},{a',b'}} → a = a' ∧ b = b'（即 Tao 习题 3.5.1，可自行阅读）。顺带一句反面：无序配对 {a,b} 不够用 —— 它只记下"有哪些元素"，不记顺序。

下面这题把编码最微妙的一幕读出来：两个坐标相同时，第二层塌缩进第一层。

练习 7（R 类）：Kuratowski 编码的退化情形 —— a = b 时 {{a},{a,b}} 塌缩成 {{a}}。 外层 Set.ext 逐元素 x : Set α 证 Iff；右到左直接 Or.inl；左到右 cases 分两支， 其中 x = {a, b} 那一支要再用一次 Set.ext（把 {a, b} 与 {a} 逐点比较）。 cases 的臂体用 have … := by … 包一层：cases 组装出来的是 match，而 match 需要一处有类型标注的位置（have 的标注正好提供它）。

theorem kura_degenerate (α : Type) (a b : α) (h : a = b) :
    {{a}, {a, b}} = {{a}} := by
  apply Set.ext
  intro x
  constructor
  intro hX
  have hmem : x = {a} := by
    cases hX with
      | Or.inl h1 => exact h1
      | Or.inr h2 =>
        exact @Eq.trans.{1} (Set α) x {a, b} {a} h2
          (Set.ext {a, b} {a}
            (fun (y : α) =>
              @Iff.intro (y = a ∨ y = b) (y = a)  -- soko:notation-ok: 复合项/λ 体的 Eq 型实参隐式反解判红（引擎边界）

                  Or.elim  -- soko:notation-ok: 复合项/λ 体的 Eq 型实参隐式反解判红（引擎边界）
                    (fun (hya : y = a) => hya)
                    (fun (hyb : y = b) => @Eq.trans.{1} α y b a hyb (Eq.symm h))
                    hy)
                (fun (hya : y = a) => Or.inl hya)))
  exact hmem
  intro h1
  exact @Or.inl (x = {a}) (x = {a, b}) h1  -- soko:notation-ok: 复合项/λ 体的 Eq 型实参隐式反解判红（引擎边界）
