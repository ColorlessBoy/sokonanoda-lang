# 文本风格规范（所有内容都必须是完整句子）

> 起因：2026-11-22 用户反馈「其实所有的内容都应该是完整的句子」。本文件是**判据**，
> `text_audit.py` 按它扫描；内容作者按它改写。

## 1. 题干 `prompt`
- 必须是**完整问句**：有前提/主语 + 明确提问，以 `？` 结尾。
- 反引号代码与符号（∈ ⊆ ≼ ⟺ ᶜ ∅ 等）逐字保留。
- 12–160 字；不泄露答案、不堆空话。
- ✅「已知 `r : Rel α β` 与 `a : α`，表达式 `r a` 的类型是什么？」
- ❌「`r a` 的类型是？」

## 2. 选项 `options`
- 必须是**完整陈述句**：能独立成句，读得通，不依赖题干补全。
- 不用括号注解代替句子（❌「`B ≼ A`（合取右支）」）；要说明就写成从句（✅「用 `And.right h` 取出合取的右支，得到 `B ≼ A`」）。
- 每题 4 个选项，长度 8–60 字，彼此**结构平行**（都是句子，不要一项句子三项短语）。
- 不许出现「以上都对/以上都不对」这类无法独立判定的选项。
- **例外（可保留代码形态）**：选项本身就是 Lean 表达式/策略名（如 `intro x`、`A ⊆ {a}`），或题干问的就是「哪个表达式/写法」。此时题干必须写成完整问句并明确「下面哪个表达式…」，选项保留代码原文即可。

## 3. 解析 `why`
- 2–4 个完整句子：先给结论，再给理由，必要时给反例。
- 不许只写公式或半句话。

## 4. 知识卡 `cards`
- `oneLiner`、`sections[].text`、`sections[].items[]` 全部是完整句子（引用代码可用行内反引号）。
- `title` 可以是名词短语（标题例外）。

## 5. 微课 `lessons`
- `goal`、`intuition` 必须是完整句子。

## 6. 术语表 `glossary`
- `oneLiner` 必须是完整句子（可以带行内代码）。

## 7. 例外
- `id`、`source`、`tags`、`kps`、代码块内容、`formula`（Unicode 公式行）不受此规范约束。
- 标题（`card.title`、`unit` 名）可以是短语。

## 8. 「切中真实要点」（2026-11-22 用户要求）

每道题必须考**这个知识点真正要考的能力**，而不是它周围的边角信息。判断标准：

- **定义型 KP**：不是问「定义是什么」（背书），而是给一个具体情境，问「这里该展开成什么 / 为什么会卡住」。
  - ❌「单射 `Injective f` 的定义是什么？」
  - ✅「已知 `inj : Injective f` 与 `h : f a = f b`，要得到 `a = b`，为什么只能把 `h` 交给 `inj`，而不能直接 `exact h`？」
- **技术型 KP**：问「在什么情况下用哪一件、顺序为什么不能反」。
  - ❌「`Or.elim` 的形状是？」
  - ✅「要从 `h : A ∨ B` 证 `C`，为什么必须准备两份证明而不是一份？」
- **边界型 KP**：问「哪一步越界了、越界的那一步换掉会怎样」。
  - ❌「满射可裂在本课程里？」
  - ✅「若想把 `Surjective f → ∃ g, RightInverse g f` 在 I.2 里证出来，你会卡在哪一步，为什么？」

数据面要求：每个知识点有 `keyPoint` 字段（一句话，写清「真正考什么能力」）；题目 `kps` 引用的 KP 必须与其 `keyPoint` 对得上（内容作者人工核对 + 抽查）。
