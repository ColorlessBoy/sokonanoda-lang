## 10. 我判定"根因报告说错了"的地方（都有读数支撑）

1. **§Q1 的 min3 夹具不是语料形状**（§3.1）：`def Set.empty (α : Type)`（显式）vs 课程库
   `def empty {α : Type}`（隐式，`courses/set-theory/lib/Set.sokonanoda:70`）。**这一个 token 决定了修法能不能收尾**：
   显式档下重试会把 `∅` 顶到"只有内核期望、没有源级期望"的 `elab_ready` 上 ⇒ `ArgElab`。
   按报告字面实现时 min3 读数**一位没动**（2 → 2），`min3b`（只换这个 token）才是 6 → 0。
2. **§Q4 候选 1 的"为什么能解出"推断漏了一步**（同 §3.1）：报告写"`NeedArgs` ⇒ 第二轮把 `∅` 对着 `Set α`
   elaborate ⇒ `Solved`"。实测这一步**不成立**——`elab_ready` 只能把**内核项**交下去，而记法的老路只吃
   **源级** `expected_src` ⇒ `Err(ArgElab)`。要补的是"把已物化的前导值代进望远镜、给操作数**源级**期望类型"
   （`notation_operand_expected`，老路本来就有），报告没提这一环。
3. **§Q5 的 185 → 64 是错的**（§7）：实测 **185 → 150**。原因是它把 `fallback_old_ok` 等同于"这 121 次会消失"，
   而实测 120 次里有 **52 次只是换原因**（`unsolved` → `unsupported input contains a meta`，老路照样接住），
   另外 4 个非目标文件因重试内的就地判定**新增** 33 次 `old_ok`。
4. **"121 次"这个数**：`fallback_old_ok_notation_unsolved` 的**实测总量是 120**（普查 §2 自己写的也是 120）；
   121 是**头名 `Set.Le` 的日志条数**（含一次 `unsupported`）。本刀把它归零的是那 120。
5. **§Q5 的"`fallback_old_err`（218）不变"**：交付版实测 **218 → 218（不变）** ✓。
6. **（本轮新增，也是**最要紧**的一条）根因报告没有区分"解出"与"换原因"。** 第一版实现（`132d0f9b`）确实把
   `unit19-solution` 的 88 次全部"清零"了，但其中 **30 次只是从 `notation_unsolved` 换成了
   `notation_unsupported_input_contains_a_meta`**（同一批站点、同一个 `Set.Le` 头、老路照样接住）⇒
   `fallback_old_ok` 只从 185 掉到 150，而 `strict ≤ loose` 被打破（90 → 165）。**"归零"这个判据只有在
   `fallback_old_ok` 总数同步下降时才算数**；交付版把它折成 **185 → 117（−68）**、`strict` 逐字不变。

## 13. 为什么有 52 次**不能靠重试**救（本轮返工的核心）

### 13.1 一句话

那 52 次的**前导值本身就是占位符**（源级 `\0soko_m{id}` ⇒ 内核 `Expr::Meta`）：内核在任何工作之前先扫一遍输入，
见到未赋值元变量立刻回 `Unsupported("input contains a meta")`（`crates/kernel/src/elab_app.rs:184-186`）⇒
**重试注定解不出**，能做的最多是把回落**换个原因**。换原因会让 `fallback_old_ok_notation_unsolved` 归零，
但那是**把指标做绿**（判据变成 `unsupported` 仍在回落），代价是把 `strict ≤ loose` 打破。

**读数**（构建 `2e1741e945b36641`，带临时探针；同一份代码的三个数）：
`unit19-solution` 的 88 次重试 = **58 次 `Solved` + 30 次 `Unsupported("input contains a meta")`**；
探针同时打出被跳过的前导值形如 `[Ident { name: "\0soko_m0", span: 0:0 }, …]`（`unit72-solution` 的 `⋃₀ (∅)` 4 次全是被这一条挡掉的）。

### 13.2 现在会触发 / 不会触发的判据（三条全满足才重试）

1. 内核回 `Ok(AppOutcome::Unsolved{ sites })`，且 **`sites` 全是 `Implicit{index}` 且 `index < missing`**
   （缺的正是记法替用户补的那几位）；
2. **`!probe::would_cut(builder, span, depth)`** —— 这次回落**不会被探测切掉**。切掉的那一趟**老路一行都不跑**
   （`probe::fallback` 直接把 `Err` 交上去，P2-5 的 `with_redo` 会在非探测那一趟重来）⇒ 物化出来的前导值
   **没人复用**，只花判定的钱。⚠ `depth` 必须用 `run` 之前捕获的那个（拿 `scope.len()` 会误判，实测把 30 个
   站点全跳掉）；
3. **前导值的内核项里没有占位符**（`has_meta`：`Expr::Meta` / `Level::MVar`）—— 就是 13.1 那条。

**另外（成本不变量，不是触发条件）**：重试算出的那份前缀会**交回老路复用**（`prefix_args_cached` + 一格
线程局部 `PREFIX_STASH`，键 = 签名 + 操作数个数 + 首操作数位置 + 作用域深度，**只消费一次**）⇒ 每个站点
**只算一次** `notation_prefix_args`，与修前完全相同（`elab.rs` 那一处调用改成调它，**零行变化**）。

### 13.3 三条收窄的实测对照（同一台机、同一批文件、`JUDGE_INFER.calls`）

| 版本 | 收窄条件 | `unit72-solution` strict / loose | `unit75` strict / loose | `unit19-solution` 剩余 | 结论 |
|---|---|---:|---:|---:|---|
| `132d0f9b` | 无（只有"三条全满足"） | **120 / 90** ✗ | 102 / 74 ✗ | 0（**靠换原因**） | 破坏 `strict ≤ loose` |
| `038d49d1` | + 占位符判据（**在** `notation_prefix_args` 之后） | 120 / 90 ✗ | — | 30 | 判定点太晚：白跑的判定钱已经付了 |
| `c2b1e8d0`/`513bb374` | + 占位符判据 **+ 探测切掉就不重试** + 前缀交回老路复用 | **90 / 90** ✓ | **74 / 74** ✓ | 30 | **交付**：与修前逐字相同 |

另外两个**被否掉**的收窄（都实测过，都不行）：
`missing >= 2`（"有兄弟可借才重试"）⇒ `unit75` 仍 102 / 74 ✗，且 `unit19` 的 30 次一位没少（那些站点的
`missing` 就是 1）；`would_cut` 单独用（不带占位符判据）⇒ `unit19` 的 30 次仍然救不回来、`unit72` 已经 90 ✓，
但它**单独**并不能让 `unit19` 归零，所以我保留了占位符判据。

### 13.4 顺带查清的既有事实（**不是**本刀引入）

`strict > loose` 在两个大课程文件上**修前就存在**：`unit19-solution` **284 vs 64**（修前修后**逐字相同**）、
`unit19-cardinal-le` **157 vs 64**（同上）。所以 `REQUIREMENTS §9.39` 的这条不变量在语料里**本来就有反例**，
它们属于内核路径自身的开销（S6），不是本刀。`strict-score.py` 的 `work_le_loose` 只量 3 个文件（
`unit01-sets-membership` / `unit12-synthesis` / `Equiv`），这三个文件恰好都在门内 ⇒ **门是绿的，但它守不住
全语料**（这条观察本身应当回写给 S6 的验收设计）。
