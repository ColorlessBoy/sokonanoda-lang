自定义记法

卷 I 的课程库里写着 infix:50 " ∈ " => Set.mem。这条命令不是语言内建的， 是课程自己声明的糖——内核从来不知道有 ∈ 这回事。

§1 为什么这门语言让课程自己定义符号

语言内建了逻辑连接符 ∧ ∨ ↔ ¬ 和箭头（→ 是 -> 的词法别名）。那是语言的选择， 任何文件零声明可用。但 ∈、⊆、𝒫、∅ 不是逻辑，是数学：它们是集合论这门课的词汇。

把这些符号写进语言，等于语言作者替所有课程决定了「哪些数学值得有符号」。 卷 I 要 ∈，线性代数课要 ∑，分析课要 ε—— 语言追不上课程。

所以做法反过来：语言只提供声明记法的命令，符号长什么样由课程说。 卷 I 把它要的十一个符号写在 courses/set-theory/lib/Set.sokonanoda 末尾， 逻辑的那个 ∃ 写在 lib/Exists.sokonanoda。

但记法是糖，不是新语义。写 a ∈ A，elaborator 把它改写成 Set.mem α a A；内核看到的始终是后者。点名形式因此不是「旧写法」—— 它就是记法展开后的那个项，永远可用。

  • α : Type
  • a : α
  • A : Set α
  • h : a ∈ A

⊢

A a

这个状态是内核判卷器回答的，不是排出来的：假设里的 a ∈ A 逐字保留了你写的记法。同一份声明换个光标位置，同一个内核又会把它印成 Set.mem α a A——什么时候保留、什么时候不保留，§4.3 给出实测的规则。

§2 八条命令

记法子集一共八个拼写：六个在算子位上，一个在 binder 位上，一个管「默认不生效」。 下表第四列是仓库里真实的出处，每条都能点开对照源码。

八条记法命令、各自的形状，以及仓库里的一条真实声明。出处给到文件与行号。
命令 形状 仓库里的真实声明 出处
infix:N lhs sym rhs，两侧同级、无结合 infix:50 " ∈ " => Set.mem lib/Set.sokonanoda:164
infixl:N 左结合 infixl:65 " ∪ " => Set.union lib/Set.sokonanoda:166
infixr:N 右结合 infixr:80 " '' " => Set.image lib/Set.sokonanoda:175
prefix:N sym a，出现在原子位 prefix:100 " 𝒫 " => Set.powerset lib/Set.sokonanoda:173
postfix:N a sym，吸收左边已经爬好的项 postfix:100 " ᶜ " => Set.compl lib/Set.sokonanoda:174
notation 零元常量，不写优先级 notation "∅" => Set.empty lib/Set.sokonanoda:171
binder_notation binder 位（表达式开头），一直吃到表达式结尾 binder_notation "∃" => Exists lib/Exists.sokonanoda:100
scoped 前缀修饰另一条记法命令；open scoped 之后才生效 scoped infix:50 " ∈ " => Set.mem crates/cli/tests/notation.rs:681

N 取 1–1000，越大绑得越紧；整条梯子夹在 ->（最松）与函数应用（最紧）之间。infix 族 N 必填，零元的 notation 不接 :N。

§2.1 课程库里的真实声明块

卷 I 要的符号集中在库的末尾。下面这十行就是全部——课程没有别的地方再声明记法， 因为同一个符号全课程只能声明一次。

courses/set-theory/lib/Set.sokonanoda:164-177 
infix:50 " ∈ " => Set.mem
infix:50 " ⊆ " => Set.subset
infixl:65 " ∪ " => Set.union
infixl:70 " ∩ " => Set.inter
infixl:70 " \ " => Set.sdiff
notation "∅" => Set.empty

prefix:100 " 𝒫 " => Set.powerset
postfix:100 " ᶜ " => Set.compl
infixr:80 " '' " => Set.image
infixr:80 " ⁻¹' " => Set.preimage
infixr:80 " ×ˢ " => Set.prod

右边一律是点名（Set.mem，不是 mem）， 因为目标名在使用点解析，而单元文件不在 namespace Set 里。 𝒫 与 ᶜ 取 100（比 ∪ 的 65 紧）， ''/⁻¹'/×ˢ 取 80。

优先级不是注释里的说法，是判过卷的：同一份课程文件里， demo_precedence_notation 写 A ⊆ A ∪ B ∪ C， 它的点名孪生写 Set.subset α A (Set.union α (Set.union α A B) C)—— 括号写死在那儿，两条都判过。

§2.2 binder 记法：一段式与两段式

∃ 在语言里不是一个关键字，而是库里的归纳类型 Exists （∀ 才是原生的，所以它不需要声明）。binder_notation 让 ∃ 出现在 binder 位，写法与 ∀ 同一层。

一段式：lib/Exists.sokonanoda:100 的声明 + unit08 的用法 
binder_notation "∃" => Exists

example (α β : Type) (f : α -> β) (A : Set α) (y : β) :
    Prop :=
  ∃ (x : α), And (Set.mem α x A) (Eq.{1} β (f x) y)

两段式多一个 guard。它的 ∈ 不必专门为 binder 声明——那就是普通的二元记法， binder 名当它的左操作数：

两段式 binder 的两种形状与它们展开成的点名形式。∀ 是原生关键字，走同一条 binder 解析路径。
写法 展开成
∃ x ∈ s, pExists α (fun (x : α) => And (Set.mem α x s) p)
∀ x ∈ s, pforall (x : α), Set.mem α x s -> p

binder 的类型有两个来源，都不做合一：标注（∃ (x : α), p） 或 guard（∃ x ∈ s, p，从 ∈ 的关系目标反解）。 两个都给不出来就报 elab-binder-notation-unsolved。

§2.3 scoped：默认不生效的记法

scoped 把一条记法挂到声明点所在的命名空间上， 不 open scoped 就不生效。它开的是记法，不是名字： open scoped Foo 之后 Foo.bar 仍然不能写成 bar。

crates/cli/tests/notation.rs:679-685 与 :700-705（仓库里唯一的 scoped 用例） 
namespace Foo
scoped infix:50 " ∈ " => Set.mem
end Foo
open scoped Foo
def p (α : Type) (a : α) (A : Set α) : Prop := a ∈ A

限制

scoped 是八条命令里唯一在 .sokonanoda 源文件里 零使用的一条。整个仓库搜下来，它只出现在上引那个 CLI 测试里 （grep -rn "scoped" --include=*.sokonanoda . 在课程与复现件里无命中）。 两段式 binder ∃ x ∈ s, p 也一样：只在测试里跑过，课程用的是 一段式 ∃ (x : α), p。本页引它们时给的是测试源，不是课程源。

§3 四条规则

记法的卖点是「零语义」。下面四条是这个卖点的具体含义，每条都附了能照着跑的证据。

§3.1 记法不是声明：它一条事件都不产生

infix / notation / binder_notation 与 import 同族：有命令、无声明。它们不进声明表、不进目标视图， 也不发 decl.checked / exercise.open / 任何别的 --json 事件。下面这份文件里 infix 那行是静默的。

记法零事件的最小复现 · 三行 
axiom mem : (α : Type) -> α -> (α -> Prop) -> Prop
infix:50 " ∈ " => mem
def use (α : Type) (a : α) (A : α -> Prop) : Prop := a ∈ A

这一条是课程门禁的支点：卷 I 的计数（目标数、checked、open） 在记法落地前后逐项相同，因为记法根本不在计数口径里。

§3.2 作用域：本文件声明之后，被 import 的从文件头

自己文件的记法声明之后才生效。写在前面就报 notation-unknown-symbol，而且它落在 parse 阶段—— 符号在词法层就已经是一个 token 了。

被 import 进来的记法不一样：它从入口文件的第一行就可用， 与 Lean 的 import 一致。这就是卷 I 二十四个单元能直接写 𝒫 A、Aᶜ、a ∈ A 的原因——它们只写了 import lib.Set，没有重声明任何符号。

代价是一条硬约束：同一个符号全课程只能声明一次。重声明 import 来的符号 会报 import-module-invalid，消息直说「同一个符号在同一文件里可以重载， 但不能覆盖 import 来的记法」。

§3.3 点名形式永久可用，两种写法判同一卷

同一命题写两遍——一遍记法、一遍点名——判卷的五元事件计数逐项相等， 退出码都是 0。这不是页面自己算的，仓库把这条钉成了测试： crates/cli/tests/notation.rs 的 assert_same_counts 对每一组夹具断言 (decl.checked, exercise.open, expr.reduced, expr.typed, diagnostic) 两个方向逐一相等。

同一命题的两种写法，各判一次。两份文件只有记法行不同；计数逐项相等，退出码都是 0。
文件 decl.checked exercise.open diagnostic 退出码
记法版 2 1 0 0
点名版 2 1 0 0

两份文件各有一个 def、一个 theorem 和一条 sorry； 差别只在 a ∈ A 与 Set.mem α a A。 所以「点名形式继续可用」不是兼容承诺，是同一份判定走了两条入口。

§3.4 展开发生在 elaborate 里，是源到源的改写

parser 只把 lhs sym rhs 记成一个带目标名的记号节点； 改写成 App 形状发生在下一步。三个可观测的后果：

  • 目标名在使用点解析。只写一行拼错目标的声明、不用它，判卷 exit 0、什么都不报；真的用一次才报 elab-notation-unknown-target。
  • 前导类型参数是展开时补的。Set.mem 的签名是 (α : Type) -> (a : α) -> (Set α) -> Prop， 而 a ∈ A 只给了两个操作数——α 由展开路径自己解出来。 这是必须的：这门语言不插入隐式实参，点名省掉 α 写成 Set.mem a A 今天仍被内核拒绝，改记法前后都拒绝。
  • 解不出就报错，不猜。补全只做裸变量匹配，没有一般合一。
