产品

为什么做这个

给已经会 Lean 4 或 Coq 的人：学习与教学两侧的实证困难，这个项目下注的三件东西， 十条硬规则各自的代价，以及明确不做的事。

§1 学习侧：三类困难，两类可以工程化

会 Lean 4 的人常把「学证明」当成学逻辑。Moore (1994) 把「过渡到证明」的困难 归成三类：概念理解、数学语言与记号、不知如何下笔。

  • 已会：intro / exact / apply / assumption / rfl / match / sorry
  • 看得懂：目标类型
  • 不知道：手边有哪条引理可用

⊢

下一步写什么

后两类可以工程化。tactic 白名单只有七个词，课程前段不引入自定义记法， 于是每一步几乎只有一个下一步；提示阶梯对准的正是「如何下笔」。 这是设计判断，不是实证结论（docs/design/set-theory-syllabus.md）。

过渡到证明的困难，与这些数字的出处。核验级别照原始调研自己的标法，不升级： [F] 全文读过；[A] 从出版方或仓储取到逐字摘要；[M] 只有书目元数据；[R] DOI 独立核对过。
结论 数字或逐字 核验级别
过渡到证明的三大困难源（Moore 1994） 概念理解；数学语言与记号；不知如何下笔 [A][R] 逐字摘要，DOI 独立核对
拆解成功率（Selden & Selden 1995） 简化陈述 8.5%，真实教材陈述 5% [A][R]
有句法知识却用不上（Weber 2001） 学生「有句法知识却用不上」 [A][R]
证明验证能力（Selden & Selden 2003） 8 名数学专业学生「倾向关注表面特征」；验证能力「非常有限——也许比他们自己和老师以为的还要有限」 [A][R]
量词换序（Dubinsky & Yiparaki 2000） 63 名学生、11 个陈述：94% 至少把一个 ∀∃ 读成 ∃∀，反向只有 5% [F]，未发表手稿
函数本体论（Breidenbach et al. 1992） 24 个本该判为「函数」的情境里只有约 40% 被同意；按表示分，图 19-40.7%、方程 25-31% 全文（作者存档扫描件的 OCR）
等势与双射判据（Hamza & O'Shea 2011） 35 名学生（含转行数学教师）：援引双射判据的人没有一个在所有题上都用它，且极少真的写出映射 全文（图像 PDF，250 dpi 栅格化 + OCR）

这些数字改了课程。单元⑦ 的导入语直接讲 40% 那一条，它的「证明或证伪」题来自 94% 那一条； 单元⑨ 与单元⑩ 强制学习者亲手把映射写出来；单元⑫ 把「读证明」单独设成一个单元。

§2 教学侧：判定权在人手里，反馈还会教错

判定今天靠三样东西：老师看一眼、答案册对一下、学习者自己的直觉。 第三样有实测——8 名数学专业学生「倾向关注表面特征」，验证能力 「非常有限——也许比他们自己和老师以为的还要有限」（Selden & Selden 2003）。

反馈本身也会教错。画布上有一道题，答案其实写全了，只是末尾多接了一个 sorry，当时的编译器却报「这条声明用了 sorry，练习还没解出」。

326和327行有问题。编译器的信息应该是 sorry 没有用，而不是 declaration 'exists_intro_rule' uses 'sorry' (exercise not yet solved)。 sorry 去掉你试试，就能编译通过了。差别很大，会让用户觉得没有证明出来。

用户原话，REQUIREMENTS.md §9，2026-09-17

已发布的二进制现在说的是另一句话。它是 warning，不影响退出码：

内核的 warning：redundant-sorry

这一行的 sorry 是多余的：前面的项已经完成了证明，sorry 不能再接在这里。

hint：删掉这一行 sorry，这条声明就会通过内核检查；若还想继续写，请把它换成真正缺少的那部分。

逐字来自 scripts/soko grade playground.sokonanoda --json 的第 38 行事件（全流共 38 行）； span 指向第 333 行，也就是 exists_intro_rule 那条声明——用户当时说的正是它。

教师技能的第一条纪律是判定永远走内核。诊断自带的 hint 就是给学习者的第一句话， 老师转述，不自己编。

文献能支持什么，不能支持什么
  • 有序对的 Kuratowski 编码没有实证研究：ERIC 的 "Kuratowski ordered pair" 返回 0 条。这是实测的否定结果，不是「没查到」。
  • 选择公理的教学同样没有：ERIC 的 "axiom of choice" teaching 返回 0 条，OpenAlex 十种措辞里有五条返回零结果。
  • 后果写进了引用纪律：单元⑤ 把 Kuratowski 降为阅读题；单元⑩ 只把 Förster 的观察当导语，并标注为作者观点、不是实证。
  • 像与原像在文献里是最薄的一环：没有一篇被广泛引用的论文研究学生对它的理解。
  • APOS 的实证基础压倒性地是微积分、线代、抽代，不是集合论。
  • 所有实证都是英文文献；中文课堂的困难分布未知。

§3 下注：三件东西，缺一件就不成立

产品愿景（REQUIREMENTS.md §1，逐字）

用户与 code agent 共同看着同一个 *.sokonanoda 文件（共享画布）： agent 从零讲课、出题；用户作答；我们自己的编译器实时给出反馈， 同一份反馈既给用户也给 agent。反馈通道以 LSP 为中心（LSP-first）。

这个愿景里有三件承重的东西。抽掉任何一件，另外两件都失去意义。

一个文件，人和 agent 看同一串字节

没有对话记录可以漂移，也没有第二份「答案文件」。agent 写进文件的东西， 用户读到的是同一份；判卷的对象就是这份文件本身。 反馈因此不用翻译——同一份 --json 事件流，两边读的是一个东西。

一个真内核当裁判

判定不能是意见。文本比对会假绿，也会假红——仓库里真写过一版 proof.rs::assumption 的文本比对草案，2026-09-07 删了。 今天 CLI 的 grade、--json 事件流、query 三条出口驱动同一份完整内核，编辑器侧走同一个 LSP。

不这么做会怎样，有实测。开练习的签名曾经不做类型检查， 于是「签名写坏了」与「还没做」在事件流里长得一样，都是 exercise.open。 一次课程自查据此全绿，作者得出了错误结论（缺口台账 G-01）。 签名受检之后，判卷只认两个信号：decl.checked 与 diagnostic。

教学循环建在上面

循环只有三步：老师讲课出题、学习者在洞里作答、老师跑判卷读事件。 出口条件是一个事件，不是感觉。

未完成是合法状态。sorry 不是错误；部分作答也支持——先写几层 fun、最后一层留 sorry，剩余目标与已引入假设会出现在 hover 与诊断里。

提示是阶梯，不是答案：每个练习挂 2 到 3 条 -- soko:hint， 编辑器逐条揭示；答案绝不写进提示。

课程文件是路线图，不是教材。

课程层只是给大模型提供路线图，具体执行层需要大模型适配各个用户、灵活调整。

用户原话，REQUIREMENTS.md §9，2026-09-07

第一层先独立成立：编译器不依赖 VS Code，也不依赖任何 agent， 但已经能解析文件、驱动完整内核、判定练习并输出结构化事件。 仓库把这一步叫「万里长城第一步」。

  • 画布：一个 .sokonanoda 文件
  • 裁判：完整内核，冻结快照
  • 老师：code agent

§4 十条硬规则，以及每条为什么存在

规则来自 REQUIREMENTS.md §2，顺序照原文。每条都换来了什么， 也都有代价；代价一列同样给出处。没有代价的规则只是口号。

十条硬规则、它们为什么存在，以及各自付出的代价。第三条与第十条的代价在后面单独展开。
规则 为什么存在 代价
内核保持完整，不因教学裁剪 内核是判卷的唯一权威。裁剪了，判出来的「对」就不算数；冻结快照与热路径不动，守住性能。 教学上的方便不能成为改内核的理由：没有累积性、Prop 大消去不可用、层级算术只收 u+1，都因此留着。
不调用官方 Lean 工具链（lean / lake / lean4export / leanc / elan） CI 离线可跑，教学内容可复现，不怕上游版本漂移。 官方那一边的东西一个都用不上：没有 lean，没有 lake，也没有 Mathlib。标准库要自己一层层补，缺口台账里有 6 条 library 欠账。
教学语法是真实 Lean 4 的子集，填完洞的声明放进官方 Lean 依然合法 学生学到的东西不能作废。这是产品的兼容性承诺。 只能用 Lean 4 的一个子集；新增语法要走「课程 + 测试 + 白名单」三件套，缺一件就进不来。
语法白名单即课程 防止编译器悄悄长成「第二套 Lean」。 语言面窄：as 与 or 模式、多 scrutinee、if/then/else 表达式都不做。
分层推进：L0 编译器 / L1 服务 / L2 编辑器 / L3 agent 协作 每层只依赖下一层的公开接口，避免返工。 今天只有 L0 完整落地；多人协作与远程是 v1 未做。
TDD 与重复测试：front 单测 + CLI 端到端 + 课程语料三层 「充分测试是大规模合作与多次大规模重构的重要资产」——用户原话。 每加一个语法点，三件套一起加；最大的一个测试文件已经 7926 行。
反馈即功能：类型、化简、打印、错误都结构化输出 同一份反馈要同时服务人和 agent，两边都不用先读文档就能驱动。 要维护协议与多个出口；有的 harness 只消费得了一部分——DeepSeek Harness 侧 LSP 只有 4 项只读操作，服务端诊断被丢弃。
判定永远走内核，不做文本比对 文本比对会假绿，也会假红。 每次判定都要真的合成声明、跑一遍完整内核；内核拒绝目前仍是 panic 转 Result，更细的分类还在后面。
用户与 agent 的使用路径零工具链依赖 要求里记着用户的纠正：cargo run 是「重大失误」。获取与运行只靠 Release 资产或 VSIX。 要维护 8 个 CLI/LSP tarball 加 9 个 VSIX；发布仍受 Marketplace 抖动影响，CI 失败台账里 10 条与 marketplace 有关。
课程标准库三层分界：L1 prelude / L2 课程标准库 / L3 单元练习 判据只有一条：「Mathlib 有 ≠ 我们不该练；Mathlib 有且没有数学内容（纯定义展开）才归库。」 每条引理都要判一次「有没有数学内容」；判错过一次——16 条内容型引理被放进库里，学习者在练习时发现答案已在库中（台账 L-05）。

子集承诺的代价

教学语法是真实 Lean 4 的子集：填完洞的声明放进官方 Lean 依然合法。 反过来不成立——section、variable、typeclass、macro、 隐式参数插入、累积性都没有。语言因此长得很慢，这是有意的。

标准库的三层分界

判据（docs/design/course-stdlib.md，逐字）

Mathlib 有 ≠ 我们不该练；Mathlib 有且没有数学内容（纯定义展开）才归库。

这条规则的起点是一段用户原话：

你的教程出的题目，在做的时候，你会发现要补充很多其他的定理，边边角角的定理， 这个是在其他的教程里头会认为是天然应该知道的，或者说是标准库里已经实现的。 这个我感觉有点暴力，所以我需要你去用这个项目，然后重新做一遍， 然后才能把这些暴力给消除掉。你要记录下这些其实是需要实现的，其实是没有的。

用户原话，REQUIREMENTS.md §9，2026-09-18

判错的代价已经付过一次：16 条内容型引理被放进课程标准库， 学习者在做练习时发现答案已经在库里（台账 L-05）。 而这条规则真的在产出东西——卷 I 一门课撞出缺口台账 24 条里的 13 条； 今天 22 条已修、2 条是长期绕行，open 为 0。

§5 这不是什么

这一页的读者大多会用 Lean 4 或 Coq。把边界写清楚，比把优点写长更有用。

不是 Lean 4 的替代品

这里写的东西在官方 Lean 里合法，官方 Lean 里的东西在这里大多不合法。 没有 Mathlib，没有 typeclass，没有隐式参数插入，也没有累积性。 它调用不了官方工具链——那是硬规则，不是疏漏。

不是通用证明助手

语法白名单即课程：parser 只认课程引入过的语法点。用途只有一个： 把判定交出去，让教学循环转起来。做得不好的功能，处置是删掉而不是留着—— 用户原话是「跟 funapply 一样实现得稀里糊涂，不如直接删了」， funapply 与 funintro 都真的删了。

不在库的大小上竞争

课程标准库只有 74 条声明，8 个模块加 1 个自检入口。判据是「纯定义展开才归库」， 所以它注定长不大。与 Mathlib 比大小没有意义；这一层存在的理由， 只是让学习者不必手写标准库该给的东西。

与 Lean 4、Coq、Agda 的逐项对照在 对照页。

§6 诚实的限制

上面每一节都有做不到的地方。集中列在这里；每一条都在仓库的 docs/ 或 REQUIREMENTS.md 里有出处。

做不到的事
  • 没有 WASM 构建。这一站不能内嵌真的 playground，只能展示源码与预录的真实事件输出。
  • 内核性质挡住的：没有累积性，def T : Type := True 会被拒；Exists.elim 的 Q 只能是 Prop；层级算术只收 u+1，u+v 与 max 写不出来。
  • 没有隐式参数插入，所以 section 与 variable 做不动——有实测，不是没排期。
  • 记法没有源码级 print-back：目标面板显示的是点名形式 Set.mem α a A，不是你写的 a ∈ A。内核 pp 冻结，这条销不掉。
  • 项目层：单文件不读 sokonanoda.toml；项目模式没有跨模块增量。
  • 平台矩阵是 8 个 CLI/LSP tarball 加 9 个 VSIX，不含 linux-armhf；发布仍受 Marketplace 抖动影响。
  • 课程计数是快照：36 个目标、329 条 checked、99 条 open。课程在长，门禁只判形状、不锁计数。
  • 没有用户数、下载量或教学效果数据；外部基准（Lean Kernel Arena）仍是 opt-in。
