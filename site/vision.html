愿景

一句话要做什么

sokonanoda 想让你在浏览器之外的普通编辑器里，学会用 Lean 4 的方式写证明。你写一个 .sokonanoda 文件，背后一整套完整的 Lean 4 类型检查内核替你判定：写对了，它就是真的证明； 写错了，它告诉你错在哪、类型对不上在哪。学习过程不靠对照答案，靠内核自己说话。

为什么做这个

已有的 Lean 教学（比如 Natural Number Game）依赖整套 Lean 工具链：安装重、版本容易漂移、课程内容难以离线复现。 我们希望把内核、预置定义、教学语料全部放进仓库，CI 离线就能跑——这样教的内容可复现、可审计，也不怕上游改版。

更关键的是判卷必须「真」。很多教学工具用文本比对或简单规则判断是否做对，学生可能绕过证明。sokonanoda 用的是完整、 可运行的依赖类型检查器：一道题判过，意味着它通过了真实的类型检查，不是形式上的「看起来对」。

它和 Lean 4、Coq 是什么关系

  • 它是真实 Lean 4 的一个受控子集。 在 .sokonanoda 里学会的写法，放进官方 Lean 依然合法。 所以你学的不是一套玩具语言，而是能迁移到真实证明助手的写法。
  • 它不是 Coq。 它的类型论取向、语法、内核都对齐 Lean 4，而不是 Coq 的 Calc 风格。
  • 内核来自 sokonanoda。 底层是一个独立的 Lean 4 类型检查器实现（Apache-2.0，来自 intgrah/sokonanoda）。我们完整移植，只在其上叠加教学接口，不改语义。

教学理念

逻辑先行

第一单元直接让你证明一个命题，而不是先背术语。等你在练习里自然发问「函数类型的类型到底是什么」时， 才引出宇宙（universe）这一概念。课程的编排跟着直觉走，而不是先堆概念再找地方用。

真内核判卷

练习里留着未完成的 sorry 洞是合法的文件状态，不是错误。你填完，内核重新判定；填错了，给你带行列和稳定错误码的诊断。 对错由内核决定，不由文本模板决定。

agent 可驱动

编译产物设计成两份视图：人读的是诊断文本，agent 读的是 JSON 事件流（每条事件一行）。同一个教学 agent 可以基于这些事件 给你出题、判卷、在卡住时讲下一步。人和 agent 面对的是同一份事实，不会各说各话。

架构示意

一条 .sokonanoda 文件怎么变成「被完整内核检查过的声明」：

教学方言文件

前端
词法 / 语法 / 轻度 elaboration，把表面语法变成内核声明
完整内核
类型检查 / 化简 / 打印，和真实 Lean 4 同一套语义
结构化反馈
检查事件 + 打印结果，分出人和 agent 两份视图
↓   解析与 elaboration   ↓   内核检查   ↓   分发给两类读者
人读的视图
诊断文本：行列、稳定错误码、中文提示
agent 读的视图
JSON 事件流：--json 一行一条，可直接驱动工具
