产品

愿景与原则

判断一个项目是否认真，看它给自己绑了哪些规则、每条又付了什么。 这一页给出终极形态、十条硬规则的原因、用户的逐字原话与教学理念。

§1 终极形态：完成的样子

终极形态（ROADMAP.md §0，逐字）

用户与 code agent 共同看着 VS Code 中打开的同一个 *.sokonanoda 文件。 agent 从零开始逐段定义概念、写出示例、抛出练习；用户在文件里作答； 我们自己的编译器实时给出反馈——同一份反馈既给用户看，也给 agent 看， agent 据此决定下一步教什么、怎么调整题目。

这不是口号，它可以拆成四个能观察到的形态。下面每一格都对应 ROADMAP.md §2 与 §3 里的一句具体要求，不是转述。

「完成」不是感觉：四个形态，以及每个形态完成时你能看到什么。
形态 完成时能看到什么 要求写在哪
一个文件是画布 讲解、代码、练习、答案区交错在同一份纯文本里；未完成的练习是合法状态，不会让整份文件编译失败；agent 能直接读写它。 ROADMAP.md §3
一份判定 内核判这份文件的每一处声明，四个问题都答得出来：这个定义过没过、这个表达式的类型与化简是什么、这道练习错在哪一段、整个文件现在处于什么状态。 ROADMAP.md §2
一台长驻服务 监听文件变更，只重编被改动的片段，已检查的定义保持不变，把结构化反馈广播出去。 ROADMAP.md §2（L1）
一次回路 agent 依据同一份反馈决定下一段讲什么、下一题出什么、哪里退回去补。出口是一个事件，不是老师的感觉。 ROADMAP.md §2（L3）

四个问题的答案全部以结构化的检查事件表达，不混在人读文本里—— 因为同一份事件要同时喂给人和 agent（ROADMAP.md §2）。

  • L0 编译器：独立成立，不依赖编辑器与 agent
  • 每层只依赖下一层的公开接口
  • 文件变更 → 增量重编 → 结构化事件

⊢

长驻服务把同一份反馈同时送到人和 agent

顺序是先把 L0 做成立，再往上接 L1 服务（常驻的 compiler service 与事件协议）、 L2 编辑器、L3 agent 协作。仓库把这一步叫「万里长城第一步」：上面的 UI、agent、 实时通道都先不做，第一层编译器先独立成立。

第一步今天已经成立：一次真实判卷

仓库根那份画布，用已发布版本的二进制判一次 （scripts/soko grade playground.sokonanoda --json），得到 30 条 decl.checked、 2 条 example.checked、 4 道练习开着、2 条 warning， 没有一条诊断。整个过程不打开编辑器，也不叫任何 agent。

课程计数是快照，不是承诺

卷 I 的 checked / open 计数来自课程门禁的一次运行， 站点数据文件里记着它的来源（counts_source）。课程在长，门禁只判形状、 不锁计数，所以这一页不拿某个具体数字当卖点。要自己量一遍： python3 courses/set-theory/tools/check.py --json。

今天走到哪一步、L1 到 L3 各剩什么，在进展页逐条列着， 包括没做的那部分。

§2 十条硬规则，以及每条为什么存在

规则原文在 REQUIREMENTS.md §2，顺序照原文。第三列不是「我们相信」， 而是这条决定记在哪——每条都能点开查到，也能看到它当初为什么被立起来。

十条硬规则、它们为什么存在，以及这条决定的出处。规则是承诺，出处才是证据。
规则 为什么存在 决定记在哪
规则 1 内核保持完整，不因教学裁剪 内核是判卷的唯一权威。裁剪过的内核判出来的「对」不算数。冻结快照同时守住性能优势：热路径一个字节不动。 REQUIREMENTS.md §2 第 1 条、§3；STATUS.md 记着最近一版内核零改动
规则 2 无官方 Lean 工具依赖：lean / lake / lean4export / leanc / elan 一律不调用 CI 离线可跑，教学内容可复现，不怕上游版本漂移。 REQUIREMENTS.md §2 第 2 条；AGENTS.md 硬规则 2（opencode 用权限 deny 强制，DeepSeek Harness 用 hooks 拦）
规则 3 教学语法是真实 Lean 4 的子集：填完洞的声明放进官方 Lean 依然合法 学生学到的东西不能作废。这是对学习者的兼容性承诺。 REQUIREMENTS.md §2 第 3 条；边界被真的量过——裸构造子名是本语言的「扩展」，真 Lean 里不可解析（台账 G-02）
规则 4 语法白名单即课程：parser 只认课程引入过的语法点 防止编译器悄悄长成「第二套 Lean」。 REQUIREMENTS.md §2 第 4 条；新语法 = 课程 + 测试 + 白名单三件套（docs/design/notation-subset.md）
规则 5 分层推进：L0 编译器 → L1 服务 → L2 编辑器 → L3 agent 协作 每层只依赖下一层的公开接口，避免返工。 REQUIREMENTS.md §2 第 5 条；ROADMAP.md §2 与 §4 给出 L0 的「包含」与「不包含」清单
规则 6 TDD 与重复测试：front 单测 + CLI 端到端 + 课程语料三层覆盖 「充分测试是大规模合作与多次大规模重构的重要资产」——用户要求，见 §3。 REQUIREMENTS.md §2 第 6 条与 §9（2026-09-07）；最近一次全量测试 1163 passed / 0 failed / 6 ignored
规则 7 反馈即功能：类型、化简、打印、错误都结构化输出，人与模型都能无文档驱动 同一份反馈要同时服务人和 agent，这是终极形态里的那句话。 REQUIREMENTS.md §2 第 7 条；协议契约在 docs/protocol.md
规则 8 判定永远走 kernel，不做文本比对 文本比对会假绿，也会假红。 REQUIREMENTS.md §2 第 8 条：proof.rs::assumption 的文本比对草案 2026-09-07 已删除；缺口台账 G-01
规则 9 用户/agent 使用路径零工具链依赖 获取与运行只靠 Release 资产或平台 VSIX，不要求 Rust/cargo。 REQUIREMENTS.md §2 第 9 条与 §9（2026-09-10，用户纠正）；AGENTS.md Setup 段
规则 10 课程标准库三层分界：L1 prelude / L2 课程标准库 / L3 单元练习 判据只有一条：「Mathlib 有 ≠ 我们不该练；Mathlib 有且没有数学内容（纯定义展开）才归库。」 REQUIREMENTS.md §2 第 10 条（2026-09-18 用户确认「进硬规则」）；判错过一次，见台账 L-05

规则 8 的故事：判定不能是意见

仓库里真写过一版 proof.rs::assumption 的文本比对草案，2026-09-07 删了。 删掉之后代价立刻显形，而且有实测：开练习的签名曾经不做类型检查，于是 「签名写坏了」与「还没做」在事件流里长得一模一样，都是一条 exercise.open。一次课程自查据此全绿，作者得出了错误结论 （缺口台账 G-01，后来在签名受检的那一版修复）。

G-01 的复现与当时的行为（docs/gaps/ledger.jsonl）

theorem t9 : 3 := sorry 曾经得到 exercise_open=1、failed=[]， 查询目标给 ⊢ 3。签名里的 3 : Nat 不是 Prop，本该报类型错误。

签名受检之后，判卷只认两个信号：decl.checked 与 diagnostic。 不拿 exercise.open 的计数当「签名没坏」的证据——这条纪律也写进了台账判据 （docs/gaps/README.md：故意不看 exercise_open 计数，G-01 就是这么假绿的）。

使用路径不依赖工具链不是设计偏好，是用户纠正出来的。记录里的原话是：

用户路径零工具链依赖（用户纠正"cargo run 是重大失误"）。

REQUIREMENTS.md §9，2026-09-10

于是获取与运行只依赖 Release 资产或平台 VSIX：8 个 CLI tarball、 8 个 LSP tarball、9 个 VSIX，加一份 SHA256SUMS，共 26 个资产。代价也落在这一条上： 发布链多了一条外部依赖，CI 失败台账 35 条里有 10 条与 Marketplace 有关。

规则 10 的故事：起点是「这个我感觉有点暴力」

这条规则来自一段用户原话，关键词是「有点暴力」：他发现别的教程当成 「天然应该知道」的边角定理，在这个项目里其实根本没有，于是要求把课程重做一遍， 把这些暴力消除掉，并记录下哪些东西是真缺的（全文见 §3）。

规则就是那次要求的制度化：每条陈述先归层，判据只有「有没有数学内容」一条。 它真的在产出东西——卷 I 一门课撞出缺口台账 24 条里的 13 条（8 条语言与工具缺口 + 5 条标准库欠账，发现端材料在 courses/set-theory/gaps/，试做稿在 docs/gaps/spike/README.md）。判错的代价也付过一次： 16 条内容型引理被放进课程标准库，学习者在做练习时发现答案已经在库里 （台账 L-05，已修）。

§4 教学理念：三个「为什么」

前面十条规则里，有几条不是工程偏好，而是教学主张。它们各自回答一个 「为什么」，而且都能在 REQUIREMENTS.md 里找到立起来的那一天。

为什么让机器判，而不是让老师判

判定的权威只有内核。文本比对会假绿，也会假红，所以规则 8 把它从仓库里删掉了。 删掉之后，仓库真的撞上过反面教材：开练习的签名曾经不做类型检查， 于是「签名写坏了」与「还没做」在事件流里长得一样，一次课程自查据此全绿 （§2 规则 8 的故事，台账 G-01）。

这不是说机器比老师会教。它说的是：判定这一步不该由人做。 人做判定时，同一条规则对不同的人会给出不同的答案，而判卷必须可复现。 教学的自由度留给别处——course/ 只是给大模型的路线图， 真正面对学习者的是一份实时调整的画布。

  • 语法白名单只认课程引入过的语法点
  • 每个语法点：front 单测 + CLI 端到端 + 课程语料
  • 判定永远走内核，不做文本比对

⊢

同一条规则对所有人给出同一个答案

为什么让课程驱动语言，而不是反过来

语法白名单即课程：parser 只认课程引入过的语法点。于是语言的生长顺序被钉住了—— 课程先撞到缺口，语言才补上，补上的同时课程里已经有它的用例。 用户把这件事说成消除「暴力」（原话见 §3），规则 10 就是那次要求的制度化。

反过来的做法是先造一套语法、再去找它的用途。仓库明确防的是这一种： 新语法必须凑齐课程、测试、白名单三件套，缺一件就进不来。 所以语言面很窄，而且长得很慢——这是有意的。

为什么文件是共享画布，而不是两个界面

终极形态里，人和 agent 看的是同一串字节：一份 *.sokonanoda 纯文本。 人看讲解、示例与练习；agent 写定义、出题、读同一份事件；编译器读同一份文件， 把类型、化简、错误与练习状态输出成结构化事件。没有同步机制要维护， 因为只有一份东西。

这件事今天已经成立，只是规模还小：§1 那次判卷读的就是同一份文件， 输出的也是同一串事件，计数与出处见 §1。练习开着是合法状态—— 未完成不导致整份文件失败。

§5 刻意放弃的东西

每条硬规则都换来了什么，也都有代价。把代价写出来，承诺才可信； 下面这些是选择，不是欠账。更细的清单在 进展页的「诚实的未完成清单」与 为什么页的规则表里。

为了内核完整

代价：内核冻结带来的三条边界
  • 没有累积性：def T : Type := <一个 Prop 值> 被内核拒绝， 专用码 kernel-prop-not-cumulative（台账 L-06，绕行）。
  • 取数据的引理写不出来：Exists.elim 的 Q 只能是 Prop，所以等势只能用 Prop 值定义，用不了 Lean 的 data 版 Equiv。
  • 层级算术只收 u+1：u+v 与 max 写不出来，因为内核的 Level::Max 没有公开构造入口。

为了零官方工具依赖

代价：标准库要自己长
  • 官方那一边的东西一个都用不上：没有 lean，没有 lake， 也没有 Mathlib。标准库只能自己一层层补，卷 I 一门课就撞出 6 条标准库欠账（台账 L-01 至 L-06，其中 L-06 是长期绕行）。
  • CI 必须离线可跑：语料与测试全部入库，代价是仓库自己变重。

为了 Lean 4 子集这条承诺

代价：语言面收窄
  • 只能用 Lean 4 的一个子集：section / variable 做不动 （本语言的应用是逐位显式的，没有隐式参数插入）、没有 typeclass、没有 macro、 没有累积性。
  • 语言按「课程撞到什么才长什么」生长：as 与 or 模式、多 scrutinee、 if/then/else 表达式都不做。

为了零工具链的使用路径

代价：整条分发链自己扛
  • 要自己维护整条分发链：8 个 CLI tarball、 8 个 LSP tarball、9 个 VSIX 平台包，加一份 SHA256SUMS，每个 Release 共 26 个资产。
  • 发布多了一条外部依赖：CI 失败台账 35 条里有 10 条与 Marketplace 有关 （docs/CI-FAILURES.md）。

为了「充分测试」与「单文件不许越长越大」

代价：两条规则互相顶
  • 每加一个语法点，三层测试一起加。最大的一个测试文件已经长到 7926 行——它自己就违反了 ~500 行的模块化惯例， 这条欠账是公开的（wc -l crates/front/src/compile/tests.rs）。
  • 两条规则会互相顶：测试要密，文件要短。仓库选择先记下欠账， 而不是为了行数少写测试。

还没有的东西：浏览器里判题

限制

没有 WASM 构建，所以这个站在浏览器里判不了题。要做需要把 crates/kernel 与 crates/front 编到 WASM， 是独立的大工程，明确列为 backlog。一期用零后端方案替代： 静态站负责讲清楚，真判卷装扩展或拿 CLI 在本地跑。

  • 内核冻结，不因教学裁剪
  • 不调用官方 Lean 工具链
  • 教学语法只取 Lean 4 的子集

⊢

代价被写下来，而不是被藏起来

这一页的原则都能追到仓库里的一次真实决定：每条规则有出处，每处代价有台账或命令。 下一步往哪走——哪些能力今天能端到端跑通、路线图的三档、诚实的未完成清单—— 在进展页；为什么这些问题值得解、每条规则换来了什么， 在为什么页。
