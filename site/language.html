功能

语言能力

这一页是这门语言今天的完整清单：每一种被接受的形式，配一个仓库里的真实例子和它的出处； 每一种形式不接受什么，同样逐条写明。边界和功能一样重要——它们才是能不能用它的判据。

§1 三十秒模型

一个 .sokonanoda 文件就是一串声明：def、 theorem、example、axiom、 inductive … end。声明之间用 -- 写讲解。 文件里没有别的结构——没有 section，没有 variable。

没写出来的答案写成 sorry。它是一个合法的未完成状态， 不是错误：编译器为它发一条 exercise.open，退出码仍然是 0。

判定永远由内核说了算。前端把源码 elaborate 成内核声明，交给完整内核终审； 判卷不做任何文本比对。

  • a : Prop
  • h : a

⊢

a

这不是排版。一行证明 by intro a; intro h; assumption 里， 光标进 assumption 时的状态就是它。复现命令： scripts/soko query state --file course/unit4-by-tactics.sokonanoda --line 37 --col 74 ——回答 step 1、这两个假设、目标 a， 声明 demo_by_assumption 的状态是 checked。

最小的真实文件只有 7 行，它把三件事一次说完：声明、自测、待办。

examples/lesson-01.sokonanoda:1-7 
-- Lesson 1: functions and types

def id : Prop -> Prop := fun (x : Prop) => x

#check id

example : Prop -> Prop := sorry
$ scripts/soko grade examples/lesson-01.sokonanoda
checked declaration id
id: Prop -> Prop
exercise open (fill the sorry)

$ 是提示符，不用输入。三行输出对应三条事件：decl.checked、expr.typed、exercise.open；加 --json 拿到的是同一份真相的 JSON Lines。

下面 §2–§6 按形式分类逐条列出这门语言接受什么、不接受什么；§7 是三层库的分界； §8 是集中起来的诚实限制，以及三处「文档说的和实测不一样」。

§2 声明：五种拼写，各有硬要求

每一种形式的「不支持」都是实测的，不是照抄文档：把中间那列的例子改坏一点， 就会看到右列说的那条诊断。

§3 归纳类型：一个块，四种行

归纳类型是一整个块，从 inductive 到 end， 中间只允许 ctor、rec、iota 三种行。 下面这个块逐字抄自仓库，它同时给出构造子、消去子与两条 ι 规则—— 也就是 Lean 教材里最劝退的那一段。

course/unit6-induction-recursion-1.sokonanoda:86-102 
inductive Color : Type
ctor red : Color
ctor green : Color
rec Color.rec {u} :
  (motive : (c : Color) -> Sort u) ->
  (mr : motive red) ->
  (mg : motive green) ->
  (c : Color) -> motive c
iota red :=
  fun (motive : (c : Color) -> Sort u) =>
  fun (mr : motive red) =>
  fun (mg : motive green) => mr
iota green :=
  fun (motive : (c : Color) -> Sort u) =>
  fun (mr : motive red) =>
  fun (mg : motive green) => mg
end

形状接受的样子 · 出处不支持的部分
参数化归纳 inductive Option (A : Type) : Type

end
course/unit7-induction-recursion-2.sokonanoda:43-46		 多名字 binder 组 (A B : Prop) 吃，无类型的 (A) 组是显式报错。 宇宙多态参数（{u} 级参数）仍不支持。
带索引归纳 inductive Vec (A : Type) : Nat -> Type
ctor vnil : Vec A zero
ctor vcons (a : A) (n : Nat) (v : Vec A n) : Vec A (succ n)
end
course/unit7-induction-recursion-2.sokonanoda:121-124		 索引是 ty 在参数之外的 Pi 望远镜，必须写在结果箭头链里。 构造子的返回类型必须是本归纳的完整应用， 否则报 kernel-ctor-result-mismatch。
消去子与 ι 规则 上面那个块里的 rec Color.rec {u} : … 与两条 iota。 显式写出来时必须与内核推导的规则逐条一致，否则报 kernel-rec-rule-mismatch。rec 可以整块省略—— 前端会按内核期望的形状自动派生递归子。
构造子的名字 规范名是 Ind.ctor（如 Color.red），裸名 red 是解析别名。 两个类型各声明一次同名裸构造子，裸名就不可判：报 elab-ambiguous-ctor-alias，这时要写全前缀名。 mutual、嵌套归纳、Quot 的教学语法都没有。

§4 项、类型与证明：值位的三种关键字

声明的值位只有三种关键字：let、match、by。 其余的一切都是普通项——lambda、应用、构造子、消去子。 类型位则是箭头、forall 与宇宙。

§4.1 match 的四条边界

前三条的复现方式都是把下面那句源码改一个地方；第四条是写法本身的约束。

match 能做什么、到哪里为止。
能不能
通配 _、绑定变量、嵌套构造子 some (succ k)、 Nat 字面量 0（脱糖为 succ^k zero）、 Bool 守卫 if cond；分支有序，首个匹配者胜。 没有元组、记录、字符串字面量模式：| "a" => … 的 parse 错会告诉你 「| 后面要跟模式：构造子、_、变量名或数字字面量」。
被匹配项是源内 inductive（分支写裸构造子名），或 prelude 内建的 Nat / Bool（分支写 Nat.zero / Bool.true）。 参数化归纳的被匹配项必须是一个局部变量，且类型写成 T 参数…： 否则报 elab-match-parameterized-unsupported。
结果类型可以从声明类型、let 或 fun 的 binder 注解推出来； 被匹配项是裸局部变量时，motive 会自动依赖它。 结果类型必须已知，否则报 elab-match-no-expected-type； 结果类型依赖索引不在 v1；嵌套与守卫下的依赖 motive 子目标退回常量（保守）。
递归构造子字段后自动插入归纳假设 binder（ih、ih2…）， 分支直接引用，递归不需要自引用。 分支必须覆盖该归纳的每一个构造子与字段位置；带守卫的分支后面要补一条兜底， 否则报 elab-match-non-exhaustive。臂体是项，不是 tactic 序列—— | red => exact green 报的是 unknown identifier `exact`。

§5 名字、作用域与记法

这一节里的命令都不是声明：它们不产生任何事件、不进声明表、不进目标视图。 它们只影响「一个短名解析到谁」和「一段源文本重写成什么」。

§5.1 namespace / open / export

namespace A … end A 之间的声明名自动带前缀（def x 的全局名是 Foo.x）。前缀在 parser 里就落定，end 的名字必须与 namespace 那行一模一样，否则报 parse-namespace-mismatch。

docs/gaps/repro/G05-namespace-open.sokonanoda:25-31 
namespace Foo
def x : Type := Prop
end Foo

-- ③ `open` 的前缀：`x` 解析到 `Foo.x`（`open` 只影响解析，不重命名任何东西）。
open Foo
def use_short : Type := x

解析顺序是固定的三步：当前命名空间链从内到外 → 精确名 → open 的前缀（按 open 顺序），第一个能解析的胜出。

docs/gaps/repro/G05-namespace-open.sokonanoda:55-64 
open Foo (x)
def use_only : Type := x

open Foo renaming x => short
def use_renamed : Type := short

open Foo in def use_local : Type := x

export Foo
def use_exported : Type := x
  • open A (a b)（只要这几个）、open A hiding a b（挡掉这几个）、 open A renaming a => b（改名）三条互斥，先过滤后改名； 被改名占位的短名不再是候选。
  • open A … in <命令> 只对紧跟的那一条叶子命令生效。
  • export A 在文件内与 open 逐字相同，但它额外记下来， 单元切换时重放——所以 export 跨 import， open 不跨。这一条在 §6 有实测。

§5.2 用户自定义记法

记法是源级糖，不是新语义：它只把源文本重写成既有的应用形状， 不产生任何事件、不进声明表、不进目标视图。点名形式永久可用，两种写法判卷结果一致。

docs/gaps/repro/G04-notation.sokonanoda:37-41 
infix:50 " ∈ " => mem
infixl:65 " ∪ " => union
prefix:100 " 𝒫 " => powerset
postfix:100 " ᶜ " => compl
infixr:80 " '' " => image
  • 零元记法不带优先级：notation "∅" => Set.empty （courses/set-theory/units/notation-cheatsheet.sokonanoda:89）。
  • 符号必须是独立 token（去掉首尾空白后不能全是标识符字符）； 优先级 N 取 1–1000。infix:N 两侧是 N/N+1， infixl:N 同级左结合，infixr:N 是 N+1/N。
  • 文件内作用域：声明之后、同文件生效，不跨 import； 但记法表本身随 import 继承。展开时自己补前导类型参数， 只做裸变量匹配——不引入元变量，也没有一般合一。
  • scoped <记法命令> 默认不生效：没写 open scoped Foo 就用那个符号，判卷 exit 1 （notation-unknown-symbol）；加上 open scoped Foo 之后 与普通记法一样判过。open scoped 只开记法，不开名字。
  • 不支持：notation3、依赖 binder、一般隐式实参推断； 后缀记法在实参位免括号明确不做——f Aᶜ 今天读作 (f A)ᶜ，改了会悄悄重分组。一元记法在实参位要写括号：f (𝒫 A)。

记法与内核的关系，最清楚的一处是它不会被打印回来。下面这条 #check 写在声明了 ⊆ 的文件里，内核的回答是点名形式：

 "inferred_type":"forall (α : Type 0), Set α -> Set α -> Prop", "type":"expr.typed"}

$ 是提示符，不用输入。源码行是 notation-cheatsheet.sokonanoda:97；事件原文是一整行 JSON，这里为可读性折了行。

  • α : Type
  • A : Set α

(∅) ∪ A ⊆ A

这是 courses/set-theory/units/notation-cheatsheet.sokonanoda 里一道未解练习 （empty_union_subset，status: open）的目标状态，复现命令： scripts/soko query goals --file "$PWD/courses/set-theory/units/notation-cheatsheet.sokonanoda"。 同一份回答里还有一个 ty 字段，它是内核给签名渲染的文本： forall (α : Type 0) (A : Set α), Set.subset α (Set.union α (Set.empty α) A) A ——同一个声明，两个字段，一个带记法一个不带。 带记法的那一个是前端走查出来的剩余目标，不是内核 pp 的产物；内核 pp 只认点名形式。 要让它 print-back 就得改冻结内核的 pp 或维护两套真相，所以明确不做。

§5.3 binder_notation：记法出现在 binder 位

courses/set-theory/units/unit08-images-preimages.sokonanoda:141-145 
binder_notation "∃" => Exists

example (α β : Type) (f : α -> β) (A : Set α) (y : β) :
    Prop :=
  ∃ (x : α), And (Set.mem α x A) (Eq.{1} β (f x) y)
  • ∃ (x : α), p 展开成 Exists α (fun (x : α) => p)； 两段式 ∃ x ∈ s, p 展开成 Exists α (fun (x : α) => And (x ∈ s) p)。
  • binder 的类型要写在括号里：这个子集不引入元变量，∃ x, p 的 x 类型没有来源。解不出时报 elab-binder-notation-unsolved。
  • 它同样不是声明：零事件，课程门禁的计数不动。

§5.4 集合字面量 {a} / {a, b}

这是新语法，不是记法：它展开成点名形式 Set.singleton α a / Set.pair α a b，目标名写死在 elaborator 里（与 + 落到 Nat.add 同族）。

crates/cli/tests/notation.rs:637-638（测试里的源文本） 
def one (α : Type) (a : α) : Set α := {a}
def two (α : Type) (a b : α) : Set α := {a, b}
  • 消歧：{ 后面是 binder 形状（{x : T} / {x y : T}） 就不是字面量，所以 f {a} 合法。
  • 只收 1–2 个元素：空 {} 与 ≥3 个元素给专用 parse 码 set-literal-shape。目标名不在本文件里（没 import 卷 I 的 lib/Set）⇒ elab-set-literal-unknown-target。
  • 诚实注记：仓库里的课程材料还没有用它们——courses/set-theory/ 里 {a} 只出现在注释与 hint 文本中，代码里写的是点名形式 Set.singleton / Set.pair。所以上面这条引的是测试源， 不是课程源。

§6 多文件：import 与 sokonanoda.toml

没有 import 的文件走单文件路径，而且从不发现、也不读清单—— 单文件就该像脚本一样直接跑。文件里出现第一条 import 之后， 编译单元才升级成「入口 + import 闭包」。

§7 三层库：prelude、课程库、练习

prelude 是受信任预置：它用 .sokonanoda 源语法书写后安装， 但从不被内核重查。它上面还有两层，分界不是「难不难」，而是一条可判定的规则：

分层判据

Mathlib 有 ≠ 我们不该练；Mathlib 有且没有数学内容（纯定义展开）才归库。

违反的样子是具体的：让学习者在证明里手写 Eq.symm、Or.elim、 mem_union 这类东西——那是「暴力」，不是练习。

  • prelude 有两种模式：默认全装；--bare 或文件里写 -- sokonanoda:prelude none 则完全不装，课程从零构造一切。

§8 诚实的限制

这一页的可信度不在于列了多少形式，而在于这些边界是不是真的。下面每一条都是 「今天做不到」，不是「暂时懒得做」——有几条是刻意的设计决定。

限制

  • 没有隐式实参插入。{x : A} 只是打印样式， 不影响类型检查，也不会被自动补上——签名要把参数给全。英文课里的原话是 「Implicit arguments are never auto-filled」。
  • 没有类型类、结构、instance。 它们与 macro 一起被列在「课程没走到之前不进白名单」。
  • 没有 section / variable。 文件里只有声明、import、作用域命令与记法命令。
  • 没有 macro。notation 已经在语言里了， 但那是记法不是 macro——它不引入新语义。
  • Type u 不支持（Type 后跟裸标识符保持应用语义， 需要时写 Sort u）；u+v / max u v / imax 不在层级语法面内，只有数字后缀。
  • match 的四条边界（§4.1）：模式种类、被匹配项的形状、 结果类型、分支完整性，每一条都会给出点名的诊断。
  • Prop / Sort / Type 是保留名。 可以声明，但编译器给一条 reserved-declaration-name 警告， 而且这个名字永不被引用——警告不影响退出码（实测 exit 0）。
  • 没有源码级 print-back。内核 pp 只认点名形式， 所以 #check 显示 Set α -> Set α -> Prop， 不是 ⊆。要做就得改冻结内核的 pp 或维护两套真相，明确不做。
  • 没有累积性。Prop ⊆ Type 在本语言不成立 （官方 Lean 4 有）：给 Sort(n≥1) 的地方给 Sort(0)， 报 kernel-prop-not-cumulative。
  • by 引擎合成的判定声明不带宇宙参数， 所以目标里出现宇宙变量时 tactic 判定会失败——Sort u 与 Sort (u+1) 都受影响。
  • 没有 WASM 构建。所以这个网站不能内嵌一个 「真的能跑」的 playground——本页所有输出都是预录制的真实运行结果，命令写在每处出处里。
  • query check 对「记法来自被 import 的模块」的文件会假红。 拿 courses/set-theory/units/unit08-images-preimages.sokonanoda 试： 它用 f '' A，而 '' 声明在 lib/Image 里。 scripts/soko query check --file "$PWD/…" 退出 1 并报一条 notation-unknown-symbol（130:46），而同一个文件 scripts/soko grade --json "$PWD/…" 是退出 0、27 条事件、0 条诊断。 原因：query 的 check / goals 先按单文件解析， 看不见 import 进来的记法。判卷以 grade 为准， 别拿 query check 的 failed[] 当判据。
    版本标注：上面这条复现属于当前发布版本。 未发布的下一批改动里它已不再复现（同一条命令、同一个文件，工作区构建退出 0、 failed: []）——发布之后请重测，并以重测结果为准。
