给 code agent

code agent 是 sokonanoda 的一等用户，不是事后接入。仓库把「怎么操作这个项目」和「怎么消费反馈」 都做成了机器能直接用的形式：一套 Agent Skill，加一份人和 agent 共用的结构化协议。

三个技能

仓库的 skills/ 目录把操作知识固化成 Agent Skill（opencode、Claude Code 等都能加载）：

  • sokonanoda-teacher：当老师的 agent。在画布上出题，用内核的 --json 事件判卷，按提示阶梯带你走下一步。
  • sokonanoda-dev：接手开发的 agent。冻结内核、TDD 三层（单元 / 内核端到端 / CLI）、文档先行的纪律。
  • sokonanoda-ci：推代码 / 发布 / 查 CI 的 agent。本地验证纪律、GitHub Actions 陷阱、失败必录。

人和 agent 共用的反馈协议

编译器产出两份视图，来自同一份事实：人读的是带行列、稳定错误码和中文提示的诊断文本； agent 读的是 --json 输出的 JSON Lines，每条事件一行。两类视图不会各说各话。

  • 事件：声明被检查、练习打开、类型被推断、项被化简、声明被打印等，每行一个。
  • 错误码：每个错误带稳定前缀（elab-* 来自前端，kernel-* 来自内核）和一条中文提示，提示直接进编辑器诊断。
  • 同一入口：无论是编辑器里的语言服务器，还是命令行，反馈都经过同一个完整内核。
sokonanoda --json your-file.sokonanoda   # 每行一个 JSON 事件，给 agent / 工具用
sokonanoda your-file.sokonanoda          # 人读的诊断文本

协议的完整事件类型和错误码见 docs/protocol.md。 取用发布二进制时按仓库版本锁定，不要用 releases/latest。

一条提示

本项目硬规则之一：判定永远走内核，禁止文本比对。给 agent 写判卷逻辑时，也请基于内核事件，而不是去比较文件文本。
