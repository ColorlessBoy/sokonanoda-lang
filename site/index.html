你和 code agent 共用一张证明草稿纸，判卷的是真内核

sokonanoda 是一个 Lean 4 式教学编译栈。你和一个 code agent 打开同一个 .sokonanoda 文件：agent 在里面写定义、举例子、出题； 你在同一个文件里把 sorry 填成证明；每一次改动都由 完整内核给出判定。

-- 画布上 agent 写下的题目（练习位留成 sorry）
theorem inter_comm (α : Type) (A B : Set α) : A ∩ B = B ∩ A := by
  sorry

把光标停在 sorry 上，编辑器给你的是内核算出来的目标状态：

α : Type
A B : Set α ⊢ A ∩ B = B ∩ A

判定只有两个来源：内核接受了这个证明项（decl.checked）， 或者内核拒绝了它（diagnostic）。没有第三条路——不是文本比对， 也不是模型打分。你看到绿色，是因为内核真的算过。

同一份判定同时给两个人看：编辑器里给你（goal 面板、诊断、hover）， --json 事件流给 agent（状态、目标、错误分类）， agent 据此决定下一步教什么、题要不要换个问法。

01怎么安装

三条路，按你的身份选一条就行。三条路都不需要 Rust、不需要 cargo， 也都锁定到同一个已发布版本：当前发布版本。

A · VS Code 扩展 推荐 · 自带 LSP 与 CLI
code --install-extension sokonanoda-lang.sokonanoda

也可以在 Marketplace 里搜 sokonanoda （扩展页）。 扩展按平台打包（8 个平台包 + 1 个 universal 回退包），包内内嵌对应平台的 LSP 与 CLI。装完打开任意 .sokonanoda 文件就能用。

B · 只要 CLI agent / headless / CI
curl -LO https://github.com/ColorlessBoy/sokonanoda-lang/releases/

把 aarch64-apple-darwin 换成你那一行： aarch64／x86_64 × apple-darwin／unknown-linux-gnu／ unknown-linux-musl／pc-windows-msvc。 tarball 里就是一个可直接执行的二进制。

C · 在仓库里 任何 harness：opencode / DeepSeek Harness / 终端
scripts/soko setup                       # 版本锁定的 CLI + LSP → 缓存（幂等）
scripts/soko doctor --json               # 就绪诊断：0=就绪 3=未就绪
scripts/soko grade playground.sokonanoda  # 判卷（--json 是事件流）

scripts/soko 是零依赖 Node 的启动器，解析顺序是 $SOKONANODA_BIN → 版本匹配的仓库构建 → 缓存 → 编辑器扩展自带 → 按版本钉下载。解析不出期望版本就绝不执行；缓存过期会拒绝运行， 并叫你先跑 scripts/soko update——它宁可停下，也不给你一个版本不对的二进制。

全部 26 个产物（8 个 CLI tarball、8 个 LSP tarball、9 个 VSIX、SHA256SUMS） 在 Releases 页； 下载一律按版本锁定，不用 latest。网络受限时先设 HTTPS_PROXY，启动器会把它交给下载器。

02核心特点

  1. 判定走完整内核，不是文本比对。 grade 的退出码就是结论：0 = 全部通过，1 = 有拒绝。 给机器看的是 --json 事件流（decl.checked / exercise.open / diagnostic），agent 拿它决定下一步。
  2. 一份文件，两个读者。 同一个 .sokonanoda 既是你的练习本，也是 agent 的状态源。 没有导出、没有第二个界面、没有人在中间转述。
  3. 教学语法是真实 Lean 4 的子集。 连接符是语言内建记法（∧ ∨ ↔ ¬ → = ≠）、 ∀／∃、by tactic 块 （intro / exact / apply / cases / constructor / use / have …）、 归纳类型与递归、宇宙 Type u、多文件 import。 你在这里练的写法，在 Lean 4 里成立。
  4. 使用路径零工具链依赖。 获取与运行只用 Release 二进制或编辑器扩展，用户与 agent 都不装 Rust／cargo；官方 Lean 工具链（lean / lake / elan）全程不调用。
  5. 两门课，每个目标都由门禁跑真内核。 入门课 11 个单元（命题、等式、函数、by、宇宙、归纳、量词、 关系、模块）；卷 I《集合论》12 个单元，从集合与隶属走到 Cantor 定理与 Russell 悖论。 每个单元都是「画布（留 sorry 的题）+ 解答钥匙」， 课程门禁 判的是形状而不是计数。
  6. 编辑器里看得见目标状态。 VS Code 扩展有 goal 面板／Infoview、练习进度树、tactic hover， 以及「这个符号怎么敲」的记法输入提示（\in、\sub、\cup …）。
  7. agent 是一等公民。 七个查询既是 CLI 又是 MCP 工具： check / state / goals / holes / hints / reduce / project； 技能目录 .agents/skills/ 会被 harness 自动发现。
  8. 没做完的事写在明处。 缺口台账 docs/gaps/ledger.jsonl 每条都带一条能复现的命令，scripts/gap.py check 会验证「状态」与「复现结果」一致——不靠人记得改。

03未来的计划

下面这些是还没做的。写在这里是为了它们不被忘掉， 而不是为了好听——每一条都指得出它在仓库里的位置。

  • 卷 II：子类型 / Sigma / 结构体。 前置债已经点名：Eq.subst 目前只支持 Prop motive，Type 层的重写还没有入口 （docs/design/course-stdlib.md 的 L-03）。先补语言，再写课。
  • 浏览器里判题。 今天判题必须有一个本地二进制（扩展内嵌或 Release 下载）；WASM 版内核还没有。
  • 增量编译常驻。 编译服务与 file.didChange 事件流（跨文件转播、setContent） 属于 L2/L3 远期，v1 未做。
  • agent 侧的 goal / Infoview 通道。 DeepSeek Harness 现在能判卷、能查询，但服务端诊断不会投递给 agent（H5 backlog）。
  • 性能：by 块的逐步判定。 现在每走一步 tactic，前端会重新判定整份文档， 所以解答文件越大、tactic 步数越多，代价越超线性。本版本实测： 卷 I 单元⑫的解答（526 行、9 道题、全 tactic）在 debug 构建下判一次约 190 秒， 已经撞上课程门禁的单目标上限。正确的修法是给「未改动的前缀」做缓存， 而不是继续抬超时上限。
  • 项目模式的剩余项。 watch、[deps]、namespace（P7 backlog）。
