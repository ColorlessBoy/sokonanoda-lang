卷 I《集合论》

入门课之后的第二卷。它不再教语言本身，而是用这门语言做数学：把「集合」当成论域上的谓词， 从隶属与子集出发，经由并、交、差、幂集、序对与笛卡尔积，走到关系、函数、像与原像， 最后到等势、Cantor 定理与 Russell 悖论。每一单元一份画布文件：讲解 + 已写好的演示 + 留着 sorry 的练习，洞由内核判定，提示分级（soko:hint）一次揭开一条。

这条路线的教学取舍写在 docs/design/teaching-project.md 与 docs/design/set-theory-syllabus.md； 课程标准库与练习的分界（哪些该进库、哪些该自己证）见 docs/design/course-stdlib.md。

怎么判卷（一条命令）

在仓库根跑课程自己的门禁：它把标准库自检、全部单元画布、全部解答各判一遍， 并打印一张表。 

python3 courses/set-theory/tools/check.py          # 人读的表 + 汇总
python3 courses/set-theory/tools/check.py --json   # 同一份结果的机器可读版

判卷永远走内核：门禁对每个目标调用 grade、看它的退出码， 不做文本比对、也不对照答案；它另外要求目标文件都在、解答不留 sorry 且覆盖画布上的每个具名练习（判据与课程规模无关，不锁计数）。门禁内部给判卷器的是 绝对路径：相对路径会让模块根解析错位，整个 import 闭包跟着失效。 退出码：0 = 全绿，1 = 有目标判负，2 = 判卷环境缺失（这时不判绿）。 要单独判一个文件： 

node scripts/soko grade "$PWD/courses/set-theory/units/unit01-sets-membership.sokonanoda"

还没装环境？装 VS Code 扩展就能在编辑器里写这些练习： 扩展内嵌了本平台的判卷器，不需要 Rust、Lean 或任何工具链。

与入门课的关系

两卷共用同一门语言、同一个内核、同一套判卷命令，差别在教什么与先修： 入门课教语言（命题与证明项、等式、函数、by、宇宙、归纳、量词）， 卷 I 用这门语言做集合论。卷 I 假设读者已学完入门课，所以不再解释 by、induction、量词是什么，直接从「集合 = 谓词」开始。

入门课（course/）卷 I《集合论》（courses/set-theory/）
教什么 语言本身：命题与证明项 → 等式 → 函数 → by → 宇宙 → 归纳 → 量词 数学：隶属与子集 → 集合运算 → 外延性 → 序对与积 → 关系与函数 → 像与原像 → 等势与 Cantor → 论域与 Russell

单元目录

编号、标题、练习数与判卷状态都由课程门禁实测生成（本页不写死任何计数）： 生成器跑 courses/set-theory/tools/check.py --json，把每个单元的实际判卷结果填进 data/site.json。「练习」= 画布上还留着 sorry 的声明数（一条练习 = 一个待填的声明）， 「已判通过」= 该单元里内核已接受的声明数（定义与演示）。 「判卷状态」是课程门禁的判定（通过 / 判负 / 目标文件缺失）：它的判据与课程规模无关—— 每个目标判卷退出码为 0、目标文件都在、解答不留 sorry 且覆盖画布上的每个具名练习、 标准库与自检不留 sorry。

目录按清单（course.json 的 schema: soko.course/2）的 卷 → 章 → 单元分组；每章标注先修（章号）、标签与计划练习数（配额）。 配额是计划不是判据：课程门禁只判形状、不锁计数，实际练习数以「练习」列为准。

卷里有什么

  • lib/ —— 课程标准库：集合的词汇 + 定义展开引理。名字按 Lean 4 标准库取证（Set.notMem_empty、Set.mem_powerset_iff、Set.Subset.refl…），所以这里学到的写法在 Lean 4 里同样成立。
  • units/ —— 单元画布：演示（已证）+ 练习（sorry）+ 分级提示。
  • units/solutions/ —— 解答钥匙（agent 专用；画布不引用它，学习者不必先看答案）。
  • tools/check.py —— 本地门禁，就是上面那条命令。
  • course.json —— 单元清单（顺序与标题），本页目录的数据源。
本页的数字与状态全部由 scripts/gen-site-data.py 在生成 site/data/site.json 时实测填入，页面只负责显示——官网永不手写计数。
