使用

安装与上手

三条路径，按你的身份选一条。每条都写到「屏幕上出现一条由完整内核给出的判定」为止， 并给出 OS 前提、怎么知道它成了，以及走不通时先查哪一行。

  • 一台机器，一个终端或一个 VS Code
  • 一个 .sokonanoda 文件

⊢

屏幕上出现一条由完整内核给出的判定

§1 先确认你需要什么

三条路径的依赖不一样。需要 Rust 的只有贡献者那一条——学习者和 code agent 都用不到 cargo。这不是「简化安装」，是硬规则：获取与运行只用 Release 二进制或平台插件， 不把 Rust 当使用前提。

三条路径的依赖边界与入口：Rust 只出现在贡献者那一行。
路径 需要 Rust 需要 Node 需要网络 入口
学习者 否 否 只在装扩展时 VS Code Marketplace
code agent / 命令行 否 是（启动器是 Node 脚本） 只在首次 setup scripts/soko
贡献者 是 是（扩展测试） 是 cargo + scripts/soko gate

学习者路径不需要 Node；装好扩展之后也不需要网络——语言服务器与 CLI 都打在扩展包里。 八个平台各有内嵌二进制的包，没覆盖到的平台由 universal 包按版本锁定下载兜底。

agent 路径不需要 Rust。Node 是启动器 scripts/soko 的运行时：一个零依赖的 Node 脚本，跨平台、不经过 shell。网络只在第一次 setup 下载时用到。 已经有 sokonanoda 在 PATH 上时，下文所有 scripts/soko … 都可以换成 sokonanoda …，两者等价。

§2 学习者：装一个 VS Code 扩展

OS 前提：macOS / Linux / Windows 都行，只要 VS Code 不低于 1.106。 这条路径没有任何命令行步骤。

  1. 在 Marketplace 装扩展 sokonanoda-lang.sokonanoda。
  2. 打开任意 .sokonanoda 文件。仓库自带的 playground.sokonanoda 就是那张画布。
  3. 到这里就完成了：语言服务器与 CLI 都已经在扩展包里，不下载、不需要 Rust。

在 Marketplace 安装扩展

怎么知道它成了。命令面板里跑一次 sokonanoda: doctor： 它会说出现在用的是哪个服务器、来自哪里（bundled / override / cache）、运行版本与扩展版本对不对得上。资源管理器里出现「练习」「项目」 「课程」三棵树，右侧辅助侧栏是目标面板，编辑器里按 alt+b 能编译当前文件。

离线也成立。有平台包的机器上，扩展装完之后全程不需要网络：八个平台 （macOS arm64/x64、Linux x64/arm64、Alpine x64/arm64、Windows x64/arm64）的包里各自 内嵌了对应平台的 LSP 与 CLI。没被这八个平台覆盖的机器，由 universal 包按版本锁定下载 兜底——它只钉当前版本，从不取 latest。

这条路径的边界只有一条：扩展里没有二进制自动更新。要换版本就重装扩展， 扩展与它内嵌的服务器永远同版本。

§3 code agent：克隆仓库，判卷走 --json

OS 前提：macOS / Linux / Windows。需要 Node——启动器 scripts/soko 是一个 零依赖的 Node 脚本，跨平台、不经过 shell。下面每一步都可以原样粘进终端。 

$ git clone https://github.com/ColorlessBoy/sokonanoda-lang
$ cd sokonanoda-lang
$ scripts/soko setup
$ scripts/soko doctor --json

$ 是提示符，不用输入。

setup 是幂等的：把版本锁定的 CLI 与 LSP 取进缓存，已经有匹配版本就不重下。 版本来自仓库里的版本钉，不是 latest——依次看 sokonanoda-version.txt、sokonanoda.toml 的 requires、Cargo.toml；多个源出现就必须一致，不一致会指名文件报错。 解析不出期望版本时启动器拒绝运行，绝不猜。

然后是就绪诊断。下面这份输出逐字抄自一次真实运行，只有版本号与绝对路径用 … 省略（本站不写死版本号，页脚显示当前版本）： 

$ scripts/soko doctor --json
{"ready": true, "version": "…", "version_source": "Cargo.toml",
 "target": "darwin-arm64", "cache": "…/.local/share/sokonanoda/bin",
 "offline": false, "launcher": "…/scripts/soko",
 "cli": {"path": "…/target/debug/sokonanoda", "present": true, "ready": true},
 "lsp": {"path": "…/target/debug/sokonanoda-lsp", "present": true, "ready": true}}
$ echo $?
0

$ 是提示符，不用输入。

读 ready，别读路径：true 且退出码 0 才算就绪。 解析顺序是 $SOKONANODA_BIN → 版本匹配的仓库构建 → 缓存 → 按版本钉锁定下载，四步。

§3.1 判卷：读事件流，不比对文本

仓库自带的 playground.sokonanoda 就是那张画布。判一次： 

$ scripts/soko grade playground.sokonanoda --json
{"human":"checked declaration Prop","name":"Prop","type":"decl.checked"}
{"human":"checked declaration True","name":"True","type":"decl.checked"}
…
{"human":"exercise open (fill the sorry)","name":"exists_intro_rule","type":"exercise.open"}

$ 是提示符，不用输入。

中间的行用 … 省略；这一跑一共 38 行，退出码 0。每行一个 JSON 对象，都带 type 与 human 两个字段。decl.checked 表示这条声明被完整内核接受过； exercise.open 表示值位是 sorry 且签名合法——它是一个合法的 进行中状态，不是错误。八种事件类型与字段契约见 docs/protocol.md。

要问「这个位置还差什么」，用单对象的 query，别自己扫事件流： 

$ scripts/soko query state --file playground.sokonanoda --line 347 --col 3
{"schema":"soko.query/1","op":"state","version":1,"ok":true,
 "data":{"decl":{"name":"forall_exists","kind":"theorem","status":"open"},
         "binders":[{"name":"P","ty":"Person -> Prop"},
                    {"name":"h","ty":"(x : Person) -> P x"}],
         "goal":"Exists Person P"}}

$ 是提示符，不用输入。

这里只抄了回答「还差什么」的三个字段（decl / binders / goal），并去掉了给编辑器高亮用的 *_runs 数组。行号取自当前 这份画布；画布改过之后，先用 scripts/soko query holes --file playground.sokonanoda 找到洞的位置，再问 query state。ok:false 不是空结果——它是 outside-declarations 这类明确的错误码。

退出码：0 和 1 是判定结果，2 和 3 是你用错了或环境没就绪。
退出码 含义 你会在这里见到它
0 答上了 / 全部通过（开放的 sorry 是合法状态） grade、query、doctor、version
1 有拒绝：内核拒绝或解析失败 grade、query
2 用法错误：参数不对 任何子命令
3 环境未就绪，启动器拒绝往下走 setup、update、doctor、gate、lsp

§3.2 技能：让 agent 知道怎么当老师

仓库里有三个角色技能，正文在 skills/<名字>/SKILL.md：

  • sokonanoda-teacher —— 当老师的主循环：在画布上出题、判卷、决定下一步。
  • sokonanoda-dev —— 接手开发：冻结内核、TDD 三层、文档先行。
  • sokonanoda-ci —— 推代码、发布、查 CI。

另外两条运维命令只给人用：sokonanoda-update（把缓存刷到仓库版本）与 sokonanoda-doctor（只读就绪诊断）。它们带 disable-model-invocation，不进模型目录。

DeepSeek Harness 会自动发现仓库的 .agents/skills/，技能名本身就是命令： /sokonanoda-teacher、/sokonanoda-dev、 /sokonanoda-ci（命令文法不允许斜杠，所以不是 /sokonanoda/teacher）。opencode 侧有 /sokonanoda/* 命令与 teacher 主 agent，启动插件会把原生 sokonanoda-lsp 接到 lsp.command 上。

§4 贡献者：需要 Rust

OS 前提：macOS / Linux。Windows 也能构建，但格式门禁只覆盖教学 crates。 三条路径里只有这一条需要 Rust 工具链。 

$ git clone https://github.com/ColorlessBoy/sokonanoda-lang
$ cd sokonanoda-lang
$ cargo build --release --locked -p sokonanoda-cli -p sokonanoda-lsp
$ export PATH="$PWD/target/release:$PATH"
$ scripts/soko gate

$ 是提示符，不用输入。

gate 一条命令跑完 CI 门禁：cargo fmt + clippy + test + playground 锚点 + 课程门禁 + 缺口台账门禁。后两步要 python3； 探不到就直接 exit 3，绝不静默跳过。

两个会看到 exit 3 的地方，都不是「你代码写错了」。第一，二进制自报版本与仓库版本不一致时， 锚点结果不可信，gate 拒绝往下跑——先 scripts/soko update，或者用 cargo run -q -p sokonanoda-cli --bin sokonanoda -- --json playground.sokonanoda 让运行中的二进制就是仓库构建。第二是缺 python3，按提示装。

改教学 crates 时不要跑 cargo fmt --all：它会重排冻结的内核快照。用 cargo fmt -p sokonanoda-front -p sokonanoda-cli -p sokonanoda-lsp -- --check， 或者干脆交给 scripts/soko gate。

§5 走不通时先查这张表

下面这些不是假想的错误，是这条安装路径上真实撞到过的。第一行是历史上最常见的一个。 表里的命令都省掉了提示符，直接复制命令本身。

症状 → 根因 → 怎么办。每一行都对应仓库里一条实测记录。
症状 根因 怎么办
启动器或判卷直接 exit 3，拒绝运行 缓存标记与版本钉不一致（历史上最常见的故障） scripts/soko update：0 = 缓存写成了，3 = 没写成（stderr 给下载原因）。scripts/soko version --json 能看 marker。
两个 doctor 结论相反：一个 ready:false、一个 ready:true 判定面不同——sokonanoda doctor 只看缓存，scripts/soko doctor 看整条解析链（含版本匹配的仓库构建） 以 scripts/soko doctor --json 为准；CLI 那个只回答「缓存对不对」。
完全离线，第一次 setup 就失败 下载需要网络 SOKONANODA_OFFLINE=1 时会给人话并 exit 3；已缓存的匹配版本照常可用；VSIX 平台包装完即完全离线。
公司代理或自签证书下下载失败 Node 的 fetch 不读 HTTPS_PROXY 启动器优先用 curl（认代理与企业 CA），失败才回落 fetch。先设 HTTPS_PROXY 指向你的代理（例如 http://localhost:7890）再试。
~/.local/share 不可写（沙箱或只读盘） 缓存写不进去 用 SOKONANODA_CACHE_DIR 指到可写目录；update 会明确 exit 3 并打印 cache NOT refreshed，不会假装成功。
机器上没有 cargo 误以为使用需要 Rust 不需要。用户与 agent 路径零工具链依赖：Release tarball 里就是可执行二进制，VSIX 内嵌 LSP 与 CLI。
Windows 上的路径、可执行位与 python 名字 跨平台差异 二进制带 .exe；缓存目录回退 %USERPROFILE%；只有非 win32 才补可执行位；python 探测顺序是 py -3 → python3 → python。
macOS 拦下 LSP 二进制 Gatekeeper 的 quarantine 属性 xattr -d com.apple.quarantine <扩展>/bin/<target>/sokonanoda-lsp；VSIX 解压出来的文件通常不带 quarantine。
Marketplace 装不上，或公司禁用 Marketplace 分发渠道限制 Release 页有 9 个 VSIX（8 平台 + universal）与 8 个 CLI tarball。headless 装法：code --install-extension sokonanoda-<平台>.vsix，或按 id 装 code --install-extension sokonanoda-lang.sokonanoda。
setup 成功，sokonanoda 仍是 command not found 启动器只解析二进制，不改 shell 的 PATH 一律用 scripts/soko 形式；或自己把缓存目录加进 PATH。
已经装了 VS Code 扩展，scripts/soko 却还要下载 启动器没有「扩展自带」这一环——文档写了它，代码里那个函数从未被调用 不要指望这条回退：用 SOKONANODA_BIN 指到扩展的 bin/<target>/，或者直接 scripts/soko setup。
编辑器面板「像没反应」，第一次按键慢 编译缓存是冷的，或在编辑器外改了依赖文件 命令面板跑 sokonanoda: build（alt+b）预热；sokonanoda: rebuild（alt+shift+b）先清缓存再编。
sokonanoda.toml 只写了 requires = "0.58"，下载失败 x.y 是约束不是版本钉，没有对应的 release tag 写完整的 x.y.z，或设 SOKONANODA_VERSION 显式给一个 tag。

这张表覆盖不到的情况，完整手册索引在 docs/。 下载下来的每个资产都可以校验：release 页有 SHA256SUMS，还有 SLSA provenance 可用 gh attestation verify <文件> -R ColorlessBoy/sokonanoda-lang 验。

§6 这一页不承诺的事

安装页最容易说漂亮话。下面几条是明确的边界，写在这里，免得你照别处的说法去试。

限制
  • 没有 WASM 构建。浏览器里跑不了内核，所以本站的功能展示全部来自 预计算的真实输出——这里不是一个能点的在线判题器。
  • cargo binstall 与 mise 标为未证实。 README 提过这两条，但仓库里没有任何 [package.metadata.binstall] 配置， 我们拿不出机器可验证的证据。不要把它们当安装路径。
  • 启动器没有「VS Code 扩展自带」这条回退。解析链只有四步： $SOKONANODA_BIN → 版本匹配的仓库构建 → 缓存 → 按版本钉下载。 AGENTS.md 与 skills/README.md 里写的第五步是死代码。
  • 两个 doctor 不是一个东西。结论不一致时，以 scripts/soko doctor --json 为准，它看的是整条解析链。
  • 扩展内不做二进制自动更新。换版本要重装扩展。
  • DeepSeek Harness 里等不到 LSP 诊断。DSH 的 LSP host 不投递 publishDiagnostics；判卷一律走 CLI --json 或 query。

这些边界有台账在守：缺口记在 docs/gaps/ledger.jsonl， 由 scripts/gap.py check 在 CI 与 scripts/soko gate 里核。 CI 失败记在 docs/CI-FAILURES.md——那是人写的纪律，不是门禁。
