# E19 评估（甲案 vs 乙案）：给记法/隐式求解器加**元变量**

> **一句话**：E19 的**收益面很窄**（今天只确证一条：G-48「两侧都是零元糖」）、**成本面很宽**
> （要动 `solve_prefix` 的求解骨架与它的报错契约），而它的**前置条件今天刚好全部到位**
> （G-43 / G-69 / G-70 已修 ✓ + T-N13 落地 ✓）⇒ 建议**先冻结基线、再做最小切片**，
> 且**先做乙案**（不动骨架的那一半）。

## 1. 要治什么（唯一确证的缺口）

* **G-48**（`open`，`painful`）：`∅ ≈ {b}` —— `≈`（`Set.Equiv`）的**两个操作数都是零元糖**，
  各自也要靠**期望类型**才能定论域 ⇒ 鸡生蛋 ⇒ `elab-notation-argument-unsolved`。
  点名写 `Set.Equiv α β ∅ {b}` ✓ 绕过。复现件
  `docs/gaps/repro/G48-notation-nullary-sugar-operands.sokonanoda`（**判红 = 缺口仍在** ✓）。
* 同族但**根因不同**（别混进来）：**G-71**（pp 形态只丢第一个隐式实参 ⇒ 展开错位 + 回读失败）——
  它的修法是"第三种实参对齐读法 + tactic 上下文别采用读不回来的 pp 形态"，**不需要**元变量；
  **G-49**（报错文本裸 de Bruijn）是诊断质量问题，也不是元变量。
* **不治**：G-56 / G-58 / G-59（良基递归与大消去）—— 那是**内核**的宇宙与一致性面；
  用户 2026-09-28 明确"那条路成本最高……**你别自己开工**"✓。

## 2. 今天的求解器长什么样（为什么"加元变量"不是小改）

* 求解入口 = `crates/front/src/compile/implicit.rs::solve_prefix`：**确定性扫描** —— 为每个待解隐式
  参数按「后续显式实参的类型头」（路线①）与「期望类型」（路线②）反解；**解不出就报专用错误码**，
  不猜 ✓。
* 记法路径 = `elab.rs::try_implicit_application`（唯一钩子）+ 路线③（富余实参落到**结果**上）；
  T-N13 又给这条链补了六处（短写/旧写法两种对齐、零元记法在函数位、嵌套位递归、模板侧展开、
  `starts_old_style` 闸门、解出值的期望类型）✓。
* **没有元变量 ⇒ 顺序敏感**：`∅ ≈ {b}` 里先解哪一侧都缺类型来源 ✗（这就是 G-48）。
* 加元变量的最小形状 = 把"解不出 ⇒ 报错"换成"解不出 ⇒ 建 `?α`，交给后续合一，最后统一判定"——
  要动 `solve_prefix` 的返回形状（`Option<Vec<Expr>>` → 带待定项的上下文）、路线①/②/③ 的失败语义、
  以及"解不出就报专用错误码"的**既有契约**（那条报错文本自己有判据 ✗）。

## 3. 成本与风险（按判据说话）

| 面 | 现状 | 加元变量之后 |
|---|---|---|
| 判定正确性（**红线**） | 非课程语料 **172 组 0 差异** ✓ | **接受面会变宽**（`∅ ≈ {b}` 由拒变收）⇒ 课程计数会涨（+N checked，**不是**红线）；**非课程语料必须逐字节不变** ✓ ⇒ 元变量必须**只在"今天报 unsolved"的路径上生效**（可判 ✓） |
| 既有报错契约 | `ElabImplicitArgumentUnsolved` 在 `crates/cli/tests/notation.rs` 有 4 条判据 | 其中一部分**不再触发** ⇒ 判据要**逐条重审**（不许为了变绿放宽 ✗），每条都要反向验证 |
| 代码面 | `implicit.rs`（求解）+ `elab.rs`（路线③） | 两处都是 T-N13 **刚动过**的热路径：判据新鲜（front **769/0** ✓）但**踩坑也新鲜**（判定缝 ✗） |
| 回归成本 | 三层判据 + 全语料对拍 | 每切一刀都要跑：front 单测 · `notation.rs` **49/0** · 课程门禁 **43/377/99/0** · 172 组对拍 |

## 4. 建议：三刀，**先冻结基线**

1. **刀 0（零行为变化）**：**重新冻结基线** —— 把今天的读数钉成数字（`--json` 逐字节哈希 ·
   课程计数 **43/377/99/0** · front **769/0** · notation **49/0** · 非课程对拍 **172 组 0 差异**），
   写进 `docs/design/e19-baseline.md`。G-48 的复现件**已经在了** ✓ ⇒ 修好那天它必须**变绿**
   （`gap.py check` 会当场报"台账写的是 open，请更新" ✓ —— 守卫是活的 ✓）。
2. **刀 1（最小切片，可回退）**：只给**记法的操作数位**引入待定参数（`?α` 只在这一处产生、
   只在这一处消费），开关当时**默认关**（`SOKO_NOTATION_METAVAR=1`；**2026-10-01 起默认开**，
   逃生门 `=0` ✓ —— as-built ⇒ `docs/design/e19-baseline.md` §9）；判据 = G-48 复现件**由红变绿**
   **且** 172 组对拍 **0 差异** ✓（两态等价，与 P 组/K1 同一套纪律 ✓）。
3. **刀 2（可选）**：把待定参数推广到 `solve_prefix` 的一般路径（`by` 块、`apply`）——
   **此时才碰** `ElabImplicitArgumentUnsolved` 的既有判据，逐条重审 + 反向验证 ✓。

## 5. 与 E20（乙案）的关系

乙案 = **不做元变量**，只把「**期望类型沿操作数传播**」加强一档：`≈` 的 `α β` 由**结果类型**
反推给两个操作数（`∅`/`{b}` 各自拿到 `Set ?`）✓。它能治 **G-48 这一档**（两侧都是零元糖时，
论域可以从 `≈` 自己的签名反推 ✓），成本约 **1/5**、**不动求解骨架**、风险低 ✓。

⇒ **建议先做乙案**；只有当"乙案治不了的形状"**再出现 ≥2 条**（新缺口各自带复现件 ✓）时，
才动甲案（元变量）✓。

## 6. 需要用户确认的两点

1. **是否接受"课程计数 +N"**：元变量会让今天判红的形状变绿（`∅ ≈ {b}` 一类）⇒ 课程会多几条
   `checked`（**不是**红线，但按纪律要你点头 ✓）。
2. **是否先做乙案**（成本低、能治已确证的那一档），把甲案留到"乙案治不了的形状 ≥2 条"再开 ✓。
