# 判据递归的锚（2026-10-20）

**起因**：用户 2026-10-16 问「修这个免疫系统的流程上有什么能改进的地方吗？感觉永远也修不完」。

## 诊断：递归没有底

```
判据 → 判据的洞 → 判据的判据 → …
```

每一层都是**代码**、都有失败模式 ⇒ **没有锚 ⇒ 无限倒退** ✗。
这就是"永远修不完"的**结构**原因 —— 不是不努力，是**这套流程没有终止条件**。

硬读数（2026-10-16）：`scripts/check-*.py` **22 个** · `docs/guard-bite.jsonl` **59 条** ·
"假绿"族（判据自己的洞）**16 条**，且当天还在长。

## 锚：不依赖"另一条判据"的客观结果

本仓已有**三条**锚（都**不是**代码判据，而是**可数/可比的客观量**）：

| 锚 | 为什么它是锚 | 当前读数（2026-10-20） |
|---|---|---|
| **`check.py` 的 `rejected` 数** | 数的是"课程判卷是否通过"，客观、可数、与判据本身无关 | **85 → 0** |
| **`cargo test` 全绿** | 跑的是被验对象的真实行为 | `front --lib` **1006/0** · `protocol` 13/13 |
| **旧档逐字节中性** | 比对两个二进制的**输出字节**，不依赖任何判据 | **252/252 · DIFFS=0** |

## 硬规矩（治"判据增殖"）

**新判据必须指向上述三条之一（或同类的客观结果）** ✓
—— **"另一条判据也绿"不算** ✗ —— 这一条把递归截断在**有限的、非代码的终点**上。

**推论**：
1. 凡声称"必红/强制/例行"的，先核**它真的拦**（`continue-on-error` · `|| true` · 守卫的输入是否真的存在）；
2. 咬不住的守卫等于没有 —— 必须有**反向验证**（它能咬住一个已知历史 bug）；
3. 判据之间**不许互为证据**（A 绿因为 B 绿、B 绿因为 A 绿 ⇒ 那不是证据，是循环）。

## 消费者导向（用户 2026-10-17 23:2x，判据本身）

> 「它**没有端到端第一性原理思考问题的能力**，比如它**不能理解守卫为什么要减少**
> （**开发变快，交付最终方案变快**），核心是**消费者导向**。
> **我拿不到结果，结果没有变好，都是失败**」

### 错在哪：把手段当成了目的

```
【守卫减少的目的（用户说的）】 开发变快 · 交付最终方案变快 · 核心 = 消费者导向（用户拿到结果）
【它做的】把「判据 22 → 17」当成目标本身 · 从没量过「开发/交付有没有变快」
⇒ 手段当成了目的 —— 而且数字越小它越觉得自己成功 ✗
```

### 判据（硬规矩）

**每条交付必须回答「用户能做什么（之前不能）」** ✓ —— 答不上来就是**没交付** ✗。
「判据数减了几个」「测试绿了几条」**都不是交付** ✓；它们只有在**换算成用户能做的事**时才成立。

**推论**：
1. 报告首格必须是**用户拿到了什么**（不是"我改了什么"）；
2. 量化交付时，量**用户侧**（能做的动作数 / 能过的语料数 / 能省的等待），不量**内部计数**；
3. 「防守卫」只在**它挡住了一个用户可见的退化**时才算交付；否则防守卫本身就是成本。
