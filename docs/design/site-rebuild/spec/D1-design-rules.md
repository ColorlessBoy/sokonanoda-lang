# D1 — 设计规则（施工手册）

> **这是实现页面时唯一需要读的设计文档。** 所有规则都是"做 X / 永不做 Y"的形式，
> 可执行、可复核。调研过程、来源考证与反例档案见
> `docs/design/site-rebuild/research/R1-design-craft.md`（参考文档，施工时不必读）。
>
> 约束：零构建静态站（手写 HTML + 单文件 CSS + 极简 vanilla JS），
> GitHub Pages 部署，中英双语，中文为主。
> 全部尺寸/颜色走 `:root` 令牌（§令牌），**组件 CSS 里不得出现裸 hex 或裸 px 字号**。

## 方向

**名称：方格纸 · 朱批**

### 三句话正当化

1. 这个产品的**产物是判定**——一个真内核告诉你"这一步通过了"或"这一步错了"，
   所以整站的色彩系统由**判定结果**驱动，而不是由"科技感"驱动：绿色只出现在
   内核真的通过过的东西上，朱红只出现在真正的诊断、更正与诚实限制上。
2. 这个产品的**材料是方格纸上的推导**——目标视图（假设在上、`⊢` 目标在下）、
   推理横线、编号单元、可复现的命令行；所以视觉语言取自**工程方格纸与批注稿**：
   冷调近白纸面、可见但不喧哗的方格、零圆角的结构容器、发丝线承担全部分隔、
   深度只靠两级表面明度而不靠阴影。
3. 这个产品的**读者是中英混排的技术读者**——所以放弃"高对比衬线大标题 + 奶油底 +
   陶土色"这套英文营销模板（中文既没有合适的 webfont，也压不住 PingFang/雅黑），
   改用单一无衬线 + 系统 CJK + 数学覆盖完整的等宽，把表现力放在**数字、符号与细线**上。

### 记忆点：推理横线（turnstile rule）

全站只有一个视觉主角：**一条发丝线，上方是"给定"，下方是"待证"**。

- 形态：`1px solid var(--rule-strong)`，宽度占满内容列，上下留 `--sp-4` / `--sp-5`。
- 用法：每页出现 **2–3 次**，位置固定——(a) hero 的文案与演示之间；(b) 每个主要
  区块的分隔；(c) 课程单元里"前提 → 目标"的视觉化。

- **不要滥用**：它一旦出现在每个小节之间就退化成普通分隔线，记忆点就没了。
  普通分隔用 `--rule`，只有上面三种位置用 `--rule-strong`。

### 方格纸网格

页面背景是一层**极淡的方格**，用 `repeating-linear-gradient` 画，**零字节、无图片**。

| 参数 | 亮色 | 暗色 |
|---|---|---|
| 格子间距（pitch） | **24px**（= `--sp-5`） | 同 |
| 线宽 | 1px | 1px |
| 线色 | `#eef1f4` | `#12161d` |
| 线色 vs 页面底色的对比度 | **1.056:1** | **1.036:1** |
| 线占页面面积 | 1/24 ≈ **4.2%** | 同 |

```css
body {
  background-color: var(--paper);
  background-image:
    repeating-linear-gradient(to right,  var(--grid-line) 0 1px, transparent 1px var(--grid-pitch)),
    repeating-linear-gradient(to bottom, var(--grid-line) 0 1px, transparent 1px var(--grid-pitch));
  background-attachment: fixed;   /* 滚动时网格不跟着动，读起来像纸 */
}
```

**"真的对齐"规则（否则网格就是装饰）**：以下尺寸**必须是 24px 的整数倍**——
页面容器的左右内边距、区块之间的垂直间距、卡片网格的 gap、hero 的上下内边距。
允许值只有 `24 / 48 / 72 / 96 / 120 / 144`。检查方式：`grep` 这些属性，
数值必须 ∈ {24,48,72,96,120,144} 或引用 `--sp-5/7/9` 的倍数组合。

> 令牌刻度里 32 与 64 不是 24 的倍数——**它们允许用于组件内部**
> （按钮内边距、图标与文字间距），**不允许用于区块级间距**。

**对比度安全规则（硬性）**：

1. 网格线对页面底色的对比度**必须 ≤ 1.10:1**。超过就是在跟正文抢注意力。
2. **所有正文色必须同时对"页面底色"和"网格线色"都 ≥ 4.5:1**——
   因为文字可能正好压在网格线上。本手册的令牌已按此验证（见 §令牌）。
3. **网格不得出现在文本容器内部**：正文块、卡片、代码块、表格都要有不透明底色
   （`--surface` / `--surface-sunken` / `--code-bg`），把网格挡住。
   网格只出现在页面的"空白地带"。
4. 暗色模式下网格线**不得比亮色模式更显眼**（对比度 1.036 < 1.056，已满足）。

### 朱批（vermilion）

第二个语义色，取自**朱砂批注**的传统：老师用红笔在你的证明上圈错、写更正。

- **只允许出现在三种东西上**：
  1. **诊断**——内核判错的信息、错误码、失败计数；
  2. **更正**——"这里写反了"这类教学提示、diff 的删除行；
  3. **诚实的限制**——"未做 / 已知问题 / 待办 / 本版本不支持"。

- **永不做装饰**：不用它画图标、画边框、画重点、画 hover 效果。
- 它与绿色是**对立的语义对**：绿 = 内核说"对"，朱 = 内核说"错"或"还没做"。
  **一个元素只能有一种语义色**，不允许同时出现绿与朱。

### 为什么每个选择都从题目推出来（防止被"优化"回模板）

| 选择 | 为什么是它，而不是别的 | 如果你改成……就错了 |
|---|---|---|
| 冷调近白纸面 | 方格纸是工程用纸，工程纸偏冷白；奶油色是 AI 设计的第一聚类 | 改成 `#F4F1EA` 一类的暖米色 → 立刻变成模板脸 |
| **可见的方格** | 这个产品的核心动作是"在格子上一步步推导"，网格是**产品的隐喻**而不是背景纹理 | 删掉网格 → 失去方向；加密到 8px → 变成噪声 |
| 零圆角结构容器 | 纸没有圆角；且 CSS 规范会在矮元素上**悄悄缩小圆角**，导致"同样"的卡片看起来不一样 | 改成统一 `border-radius: 1rem` → 层级信息消失 |
| 发丝线承担全部分隔 | 推理横线是数学排版的原生装置 | 改用阴影分块 → 纸面隐喻崩掉 |
| 深度靠表面明度 | 暗色下阴影不可见；纸面本来就没有阴影 | 给每张卡加 `box-shadow` → 变成 SaaS 卡片套装 |
| 绿 = 内核通过过 | 产品最独特的资产是"真内核判卷"，颜色应该由判定驱动 | 把绿用作品牌色到处刷 → 语义污染，审计立刻失败 |
| 朱 = 诊断与限制 | 朱批是"有人在你的作业上写过字"的视觉证据 | 把朱用作第二个品牌色 → 同上 |
| 无衬线 + 系统 CJK | 中文占九成，系统 CJK 是黑体；拉丁衬线会在同一段里跟中文黑体打架 | 引入拉丁衬线正文 → 中英混排骨架冲突 |

### ⚠️ 本方向与两条"AI 默认长相"相邻——必须知道边界在哪

公开的反 AI-slop 指导把生成式设计聚成五类，其中**第 2 类**是
"近黑底 + 单一荧光绿或朱红强调色"，**第 3 类**是
"**宽幅报纸式排版：发丝线 + 零圆角 + 密集的多栏**"。

**本方向同时踩在第 2 与第 3 类的边上。** 这不是可以含糊过去的事——
判据是那句话：这些特征是**被题目推出来的选择**，还是**闭眼就会写的默认**。
我们的答案是前者，但**必须靠下面四条把边界钉住，否则会漂回模板**：

| 与第 3 类的分界 | 我们**必须**保持 | 一旦变成这样就退回默认 |
|---|---|---|
| 栏数 | **单栏**，正文 `--measure: 40rem`，大量留白 | 出现多栏、密排、"报纸感" |
| 零圆角 | 零圆角**只给结构容器**；控件仍是 3px | 连按钮/输入框也削成直角 |
| 发丝线 | 发丝线是**推理横线**（有语义），每页 2–3 次 | 每条边界都画线，退化成普通分隔 |
| **方格** | **方格必须可见**（1.056:1）——它是产品的隐喻 | 把方格删掉 → 就只剩"细线 + 直角"这个空壳 |
| 与第 2 类的分界 | 我们**必须**保持 | 一旦变成这样就退回默认 |
|---|---|---|
| 底色 | **亮色为主**（`--paper: #f5f7f9`） | 做成近黑底 |
| 强调色亮度 | 绿 `#1e6b4c` / 朱 `#c8371c` 是**深色、低亮度**，用于文字与实底 | 换成荧光绿 / 亮朱红 |
| 强调色用途 | **语义的**：绿=内核通过过，朱=诊断与限制 | 当品牌色做装饰 |
| 强调色面积 | 每屏实底强调元素 ≤ 1 个，像素占比 ≤ 10% | 大面积铺色 |

**复核**：截图与"近黑底 + 荧光绿""报纸密排"两个印象对比，一眼像就是漂了。

**补充判据（比"用什么颜色"更本质）**：Anthropic 自家的品牌色板
（`#faf9f5` 奶油底 + `#d97757` 陶土橙）**正是它自己的反 AI-slop 文档点名的第一类长相**——
而那是一个正当的品牌色板。**所以 tell 不在颜色本身，在于颜色是不是被题目推出来的。**
本方向的每个色都有题目依据（绿=内核判定，朱=朱批，冷白=工程纸），这就是它成立的理由。

## 硬禁令

> **这一节是防止 AI 味回归的核心。** 每条都是"永不做"，没有例外条款。

### A 档：任何情况下都错

| # | 永不 | 替代做法 |
|---|---|---|
| A1 | 标题用渐变文字（`background-clip: text`） | 纯色墨。要强调用字重、字号或一条手绘下划线 |
| A2 | 标题里只把一个词改成斜体/粗体/另一种颜色 | 整个标题同一处理；强调靠句子本身 |
| A3 | 编造数字、证言、logo、客户数、百分比 | 用真数字；没有就写 `—` 加一个灰底标注"待确认"，或换掉整个版式 |
| A4 | 用 CSS 画假的浏览器/手机/终端/IDE 窗口（假 URL 栏、假红黄绿点） | 真实截图包 `<figure>` + `<figcaption>`；或 `<pre>` + 排版式边框（上下细线 + 一个文字标签） |
| A5 | emoji 当图标（✨🚀⚡🔥🎯✅） | 一个图标库，或干脆只用文字。**本站目前 0 emoji，保持** |
| A6 | 混用多个图标库 | 只用一个；或不用图标 |
| A7 | `transition: all` | 显式列出属性：`transition: background-color var(--dur-1) var(--ease-standard)` |
| A8 | 焦点环淡入 | 焦点环**瞬间出现**，永不给 `outline` / `box-shadow` 加过渡 |
| A9 | 动画 `width` / `height` / `top` / `left` / `margin` / `padding` / `box-shadow` | 只动 `transform` 与 `opacity` |
| A10 | 只有 hover、没有 focus/tap 等价物 | 每个 hover 效果必须有 `:focus-visible` 对应；hover 效果用 `@media (hover: hover)` 包起来 |
| A11 | 颜色作为唯一的信息通道 | 加文字、符号或形状（如 diff 必须有 `+`/`−` 字符） |
| A12 | 正文对比度 < 4.5:1（**不四舍五入**，4.499 不达标） | 用 §令牌 的值 |
| A13 | 自动播放带声音的媒体 | 一律 `muted playsinline`；或不做视频 |
| A14 | 自动轮播 / 自动前进 | 不做轮播。若必须有，给暂停按钮（WCAG 2.2.2：自动播放超过 5 秒即需暂停机制） |
| A15 | 任何宽度（320–1920px）下出现横向滚动 | `html, body { overflow-x: clip }`（用 `clip` 不用 `hidden`——`clip` 保留 sticky/fixed） |

### B 档：旧站命中的具体 tell 及其对策

| # | 旧站的做法 | 改成 |
|---|---|---|
| B1 | `--radius: 10px` 刷所有卡片，另有 5/6/7/8/999 共 6 种圆角 | 只有三档：`--r-0`（结构容器）、`--r-1`（控件）、`--r-full`（仅状态点，每屏 ≤1 个） |
| B2 | 每个盒子都是 `1px border + var(--radius) + var(--surface)` | 深度靠**表面明度分级**；边框只在真的需要边界时用 |
| B3 | `.card .step`——每个标题上方的 eyebrow 小标签（"给学习者"） | **删掉**。它不编码任何信息 |
| B4 | `.card .step { letter-spacing: .5px }` | **删掉**。中文永不加字距（会连带破坏着重号与行间线的对齐） |
| B5 | `.entry-strip` 每个链接都带 `→` | **删掉箭头**。层级靠位置与字重表达 |
| B6 | 代码块底色 `#11161a`（亮页里嵌一块带色偏的近黑） | 代码块与页面**同极性**：亮页用 `--code-bg: var(--surface-sunken)`，暗页用 `#12161b` |
| B7 | 三套不同的深色代码底色（`#11161a` / `#1e1e1e` / `#252526`） | **一套**，全部走令牌 |
| B8 | `.stat { text-align: center }` 居中数字 | 数字列**右对齐** + `font-variant-numeric: tabular-nums` |
| B9 | `--max: 960px` 通吃所有内容，正文行长 ≈112 拉丁字符 | 拆成 `--measure: 40rem`（正文）与 `--wide: 68rem`（外壳） |
| B10 | 17 个不同的 `font-size`（含 13.5px / 12.5px / 0.82rem） | 只用 `--fs-*` 九档 |
| B11 | `gap` 有 14 / 22 / 26 等不在任何网格上的值 | 只用 `--sp-*` 刻度 |
| B12 | 全站 0 个 `transition`、0 个 `prefers-*`、0 个 `:focus-visible` | 补状态反馈 + 暗色模式 + 焦点环 |
| B13 | `.section-title` 与 `.section-sub` 用负 margin 互相抵消 | 只用单向 `margin-block-start` + owl 选择器（§间距与布局） |
| B14 | 无 favicon / og / canonical / theme-color | 全部补上 |
| B15 | 内页 `<title>` 只有"关于"/"课程"，不带品牌 | 改为 `页面名 — sokonanoda` |
| B16 | 缺 `tabular-nums` | 所有数字列、计数、版本号加 `font-variant-numeric: tabular-nums` |
| B17 | 页面里的 `→` 有 25 处（含链接文本） | 只保留**真实的箭头语义**（如 `⊢` 目标、命令输出），装饰性的一律删 |

### C 档：合法但已成为默认——必须能说出理由才可用

以下每一条都不是"错"，而是**闭眼就会写的东西**。用之前必须能回答
"为什么这个 brief 需要它"：

| 项 | 什么时候才允许 |
|---|---|
| 三列等宽卡片网格 | 内容**真的是三个并列的东西**，且**必须打破等宽等高**（第一张通栏或大小不一） |
| 居中元素 | 每屏**最多一个**，且不能是标题或正文 |
| 编号 `01/02/03` | 内容**真的是序列**。本站课程单元①②③…⑫ 是真序列 → **允许**；"安装两条路径"不是 → 禁止 |
| 居中 hero | 本站不做（hero 是左对齐分栏） |
| 药丸形标签 | 每屏 ≤ 1 个 |
| 左侧 4px 粗色条 | 只允许给**诊断/限制**类 callout，且必须配一个**文字标签**（"限制"/"注意"/"已废弃"） |
| 衬线字体 | 见 §排版 的明确结论：正文不用 |

## 令牌

**复制这一整块进 `site/assets/style.css` 的最上方。**
所有颜色对已实算验证：**正文对全部 ≥ 4.5:1，控件边界 ≥ 3:1，0 处不达标**。
注释里的数字是**实测比值**，改动任何一个色值都必须重算。

**验证口径**：文字可能压在网格线上，所以每个正文色都对
**页面底色 / 网格线色 / 表面色**三者都验过。

```css
/* sokonanoda — 方格纸 · 朱批
   绿 = 内核真的通过过；朱 = 诊断 / 更正 / 诚实限制。两者都只做语义，不做装饰。 */
:root {
  color-scheme: light dark;

  /* ---- 方格纸 ---- */
  --grid-pitch: 24px;      /* 必须是 --sp-5；区块级间距取它的整数倍 */
  --grid-line:  #eef1f4;   /* vs --paper 1.056:1 —— 可见但不抢注意力（上限 1.10） */

  /* ---- 表面：深度靠明度分级，不靠阴影 ---- */
  --paper:           #f5f7f9;  /* 页面底（冷调近白，非奶油色） */
  --surface:         #ffffff;  /* 抬起一级：卡片、表头 */
  --surface-sunken:  #ebedf3;  /* 下沉：代码块、well、斑马纹 */
  --surface-overlay: #f0f2f6;  /* 悬浮层底 */

  /* ---- 墨色（三级；括号内为 on paper / on grid / on surface） ---- */
  --ink:    #14171c;  /* 正文        16.73 / 15.84 / 17.96 */
  --ink-2:  #4a5159;  /* 次要         7.49 /  7.09 /  8.04 */
  --ink-3:  #646c76;  /* 元信息       4.95 /  4.69 /  5.32  ← 下限，勿再浅 */
  --ink-invert: #f5f7f9;

  /* ---- 线 ---- */
  --rule:        #d9dee5;  /* 装饰性分隔（无 3:1 要求） */
  --rule-strong: #bac2cc;  /* 结构性分隔 + 推理横线 */
  --border-control: #7c8691; /* 控件边界，3.70 on surface / 3.26 on grid ✅ */

  /* ---- 语义色 1：内核判定绿 ---- */
  --acc:        #1e6b4c;  /* 实底（白字 6.44） */
  --acc-ink:    #14523a;  /* 绿文字 8.51 / 8.06 / 9.14 */
  --acc-wash:   #e7f0eb;  /* 绿底（acc-ink on it 7.86） */
  --acc-border: #54906e;  /* 绿边 3.76 / 3.31 ✅ */

  /* ---- 语义色 2：朱批 ---- */
  --verm:       #c8371c;  /* 实底（白字 5.23） */
  --verm-ink:   #b83318;  /* 朱文字 5.55 / 5.26 / 5.96 */
  --verm-wash:  #fbebe9;  /* 朱底（verm-ink on it 5.15） */

  /* ---- 注意（第三种，仅用于"请注意"，不是诊断） ---- */
  --warn-ink:   #6b4407;  /* 7.97 / 7.55 / 8.55 */
  --warn-wash:  #faf2e0;

  /* ---- 焦点环：用 outline，不用 box-shadow ----
     outline 不占空间、不重排、跟随 border-radius（Chrome94/FF88/Safari16.4+），
     且属 ink overflow 不受裁剪；box-shadow 会被 overflow 裁掉，且 Windows
     高对比模式下不显示。兜底：outline: auto 5px Highlight; */
  --ring-color:  var(--acc);
```

## 排版

### 衬线：**不用**（明确结论）

**正文、标题、UI 一律无衬线。** 三条理由，按重要性排序：

1. **中文占九成，而中文只能用系统栈（黑体）。** 拉丁衬线只会在拉丁片段上渲染
   （标识符、命令、版本号）——恰恰是那些位置你更想要等宽或无衬线。
   若整段中英混排，中文黑体与拉丁衬线是**两套骨架**，中文部分会显得偏轻。
2. **CJK 衬线 webfont 是数 MB 级**，与零构建 + 整站 HTML 仅 ~72 KB 的现状直接冲突。
3. "高对比衬线大标题 + 奶油底 + 陶土色"是**被点名的第一类 AI 长相**，
   而中文站做这套必然做不完整，只学到一半的模仿最糟。

**唯一的例外（有明确边界）**：若将来为**单篇长文阅读页**（如课程讲解）做排版，
可以只对**拉丁部分**用**系统衬线栈**——它零字节：

```css
/* 仅限长文阅读页；中文仍走系统黑体 */
--font-read: "Iowan Old Style", "Palatino Linotype", Georgia, "Songti SC",
             "SimSun", "Noto Serif CJK SC", serif;
```
**默认不做。** 不要把这个例外扩散到首页或文档页。

### 字族：2 个

```css
--font-ui:   system-ui, -apple-system, "Segoe UI", "PingFang SC",
             "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC",
             "Source Han Sans SC", sans-serif;
--font-mono: "Noto Sans Mono", ui-monospace, SFMono-Regular, Menlo,
             Consolas, monospace;
```

**`⊢` 是选等宽字体的第一道门槛。** 实测 Menlo、SF Mono、Monaco、Consolas、
Source Code Pro、JetBrains Mono、Geist Mono、Roboto Mono、Inter、
**以及本栈里的 Hiragino Sans GB** 都**没有** `⊢`（U+22A2）。
浏览器逐字回退 → 等宽代码块里混进宽度不同的字形，对齐静默崩掉。
**结论：自托管 `Noto Sans Mono` 的 woff2 子集**（latin + 本项目用到的
`⊢ ∀ ∃ → ↔ ∧ ∨ ¬ ≠ ≤ ∈ ⊆ ⟨ ⟩ α λ ℕ ⟶ ↦ ⇒ ⊤ ⊥`，约 15–25 KB），
让它成为**首选且确定**的字体，而不是"碰运气命中"。

### 字号、行高、行长

| 规则 | 值 | 检查 |
|---|---|---|
| 字号只取九档 | `--fs-xs … --fs-4xl` | `grep -oE 'font-size:[^;]+' \| sort -u \| wc -l` ≤ 9 |
| 行高**无单位** | `--lh-*` | `grep -E 'line-height:[^;]*px'` 为空 |
| 行高随字号**递减** | 1.15 → 1.3 → 1.7 | 目视 h1 比正文紧 |
| 正文行长 | `--measure: 40rem` | 最宽正文块 ≤ 640px |
| 正文行高 ≥ 1.5 | 中文 1.7 | WCAG 1.4.12 |
| 文本容器**不设固定 `height`** | 用 `min-height` 或 padding | `grep -E '^\s*height:'` 为空 |
| 标题上方空白 ≥ 下方 1.5 倍 | 用 `margin-block-start` 实现 | 目视 |

### 数字

**任何出现在列里、或会随数据变化的数字，一律 `tabular-nums`。**

```css
table, time, .counter, .stat, .version { font-variant-numeric: tabular-nums; }
code, .id, .version { font-variant-numeric: tabular-nums slashed-zero; }
```

命中位置：`site.json` 的计数（checked / open / targets / units）、版本号并排对比、
`.stat` 数字、`table.compare` 数值列、代码行号。
**本项目的可信度就是它的数字**——宽度跳动会让"真数字"看起来像随手写的。

### 代码块的字体设置

```css
code, pre, kbd, samp {
  font-family: var(--font-mono);
  font-variant-ligatures: none;              /* 见下 */
  font-feature-settings: "liga" 0, "calt" 0; /* 两个都要，某些引擎只认低层 */
  tab-size: 2;                               /* 浏览器默认是 8 */
}
```

**为什么必须关连字**：JetBrains Mono / Fira Code 把 `->` 渲染成一个箭头字形，
而这个语言里 `→`（U+2192）是**真实存在的记法**。若 `->` 看起来和 `→` 一样，
读者无法从屏幕判断源码里是哪个字符，而且复制出来是 ASCII `->`，与视觉不符。
**在一个"判定永远走内核、禁止文本比对"的项目里，让排版对字符撒谎是不可接受的。**

### 排版禁令

- 永不在标题里给单个词换色/斜体/加粗。
- 永不用全大写做标签。
- 永不在内容上方加 eyebrow 小标签。
- **永不给中文加 `letter-spacing`**（会连带破坏着重号与行间线的对齐）。
- 永不 `text-align: justify`（产生"白河"，且 WCAG 1.4.8 明确不推荐）。
- 永不 `text-rendering: optimizeLegibility`（非标准，且会打开连字——与上条冲突）。
- 中文与拉丁/数字之间**加一个空格**；全角标点与字符之间**不加**空格；
  度数与百分比**不加**（`90°` `15%`）。

## 间距与布局

### 刻度

```
--sp-1..9 = 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96
```

| 用途 | 取哪些 |
|---|---|
| 紧邻元素（图标与文字、标签与边框） | `--sp-1` / `--sp-2` |
| 组件内部（按钮内边距、卡片内边距） | `--sp-3` / `--sp-4` / `--sp-5` |
| 区块之间 | `--sp-7` / `--sp-8` / `--sp-9` |
| **区块级间距同时必须是 24 的整数倍**（对齐方格） | `24 / 48 / 72 / 96`（= `--sp-5` 的 1/2/3/4 倍） |

**规则是"每个值必须在命名刻度上"，不是"必须是 8 的倍数"。**
`--sp-3`(12) 与 `--sp-1`(4) 是合法的半步；**14 / 18 / 22 / 26 永远不合法**。

### 单向 margin + owl 选择器

```css
.flow > * + * { margin-block-start: var(--sp-5); }
```

**只用 `margin-block-start`，永不用 `margin-bottom`。** 理由：双向 margin 会产生
"多余的尾边距"和父子塌陷导致的双倍间距。单向 margin 让塌陷问题**不再存在**。

**逃生口**：若某处间距不符合预期，把它放进 `display: flex` 或 `grid` 的容器——
**flex/grid 容器里 margin 不塌陷**。

### 容器宽度

```css
.wrap  { max-width: var(--wide);    margin-inline: auto; padding-inline: var(--sp-5); }
.prose { max-width: var(--measure); }
```

**正文永远不占满 `--wide`。** 旧站用同一个 `960px` 装所有内容，
导致正文行长 ≈112 拉丁字符（超 WCAG 1.4.8 上限 40%）。
**修法是把"外壳宽度"与"正文宽度"拆成两个变量**，不是缩小外壳。

### Grid vs Flow

| 用普通文档流 + `max-width` | 用 CSS Grid |
|---|---|
| 散文、列表、任何一维顺序内容 | 页面外壳（导航 / 正文 / TOC） |
| 条目数未知的内容 | 真正二维对齐（表格用 `<table>`，不用 grid） |
| | 图 + 说明的并排 |

**三列等宽卡片只在内容真的是三个并列的东西时才用，且必须打破等宽等高**
（第一张通栏，或大小不一）。

### 其他布局规则

| 规则 | 做法 |
|---|---|
| 全站左对齐 | 例外只有两个：`figcaption`、表格数字列（**右对齐**） |
| 每屏最多一个居中元素 | 标题与正文永不居中 |
| 相邻区块间距**不等值** | `--sp-7` / `--sp-8` / `--sp-9` 交替 |
| **带背景或边框的容器 ≤ 2 层** | `<main>` → `<section>`（可有 1 条上分隔线）→ 内容直接排布，不再套卡片 |
| 一个 `<section>` 一个想法 | 出现两个 `<h2>` 就拆开 |
| `html, body { overflow-x: clip }` | 用 `clip` 不用 `hidden`（保留 sticky/fixed） |
| 带图的 grid 轨道写 `minmax(0, 1fr)` | 裸 `1fr` 的最小值是图片固有宽度，会撑破 |
| 用 `gap` 排同级元素，`margin` 只做光学微调 | — |

## 颜色

### 两个语义色 + 一条审计规则

> **绿只出现在「内核真的通过过」的东西上；朱只出现在「真的是诊断或诚实限制」的东西上。
> 任何一处语义色都要能回答："这里有什么真实判定在背后撑着？"答不上来就是 bug。**

| 元素 | 用绿？ | 用朱？ | 理由 |
|---|---|---|---|
| `checked` / `failed` 这类**实测**计数 | ✅ | ❌ | 背后是 gate 的真实运行结果 |
| 已发布的版本号 | ✅ | ❌ | 背后是真实 release |
| 主 CTA（安装） | ✅ | ❌ | "进入已验证路径"的入口 |
| 课程单元的"通过"状态 | ✅ | ❌ | 背后是 gate 结果 |
| 内核判错的信息 / 错误码 / 失败计数 | ❌ | ✅ | 真正的诊断 |
| "这里写反了"这类教学提示 | ❌ | ✅ | 更正 |
| **"未做 / 已知问题 / 待办 / 本版本不支持"** | ❌ | ✅ | **诚实的限制** |
| diff 的删除行 / `sorry` 洞 | ❌ | ✅ | 未解的东西 |
| "请注意"类提示 | ❌ | ❌ | 用 `--warn-*` |
| 装饰性分隔线、图标、背景色块 | ❌ | ❌ | 没有判定语义 |
| 导航当前页 | ❌ | ❌ | 用 `--ink` + 字重 |

**一个元素只能有一种语义色**，不允许同时出现绿与朱。

### 面积与强调纪律

| 规则 | 值 |
|---|---|
| 每屏**实底**强调元素 | ≤ 1 个 |
| 强调色像素占比 | ≤ 10%（截图直方图统计，不靠眼睛） |
| 对比变体数 | ≤ 3 种 |
| 同时"大"的元素 | ≤ 2 个 |

### 暗色模式

| 规则 | 值 |
|---|---|
| 底色不用纯黑 | `#0f1216`（带冷色偏） |
| 字色不用纯白 | `#e5e9ee`（on surface 14.17:1，刻意不取最大） |
| 强调色**提亮 + 降饱和** | 绿 `#1e6b4c` → `#5fb98c`；朱 `#c8371c` → `#e2603f` |
| 抬升靠**表面明度** | `#0f1216 → #171b21 → #1e232b` |
| 阴影几乎不可见 | 暗色浮层改用"表面明度 + 一圈 `--rule-strong` 发丝边" |
| 网格线不得更显眼 | 暗色 1.036:1 < 亮色 1.056:1 ✅ |

实现方式：`@media (prefers-color-scheme: dark)` 覆盖 `:root` 的**语义层**变量，
并在 `:root` 声明 `color-scheme: light dark`。
**不用 `light-dark()`**（2024 才 Newly available，本站零构建无 polyfill）。

### 颜色禁令

- 永不使用渐变作为装饰背景（渐变只允许用于**功能性淡出**，如横向滚动容器的边缘遮罩）。
- 永不使用纯 `#000` / `#fff` 作为底或字。
- 永不让中性色零彩度（所有灰都带一点冷色偏）。
- 永不用颜色作为唯一信息通道（diff 必须有 `+`/`−` 字符 + 左侧色条）。
- 永不把强调色用于装饰。

## 深度

### 边框 vs 阴影

| 场景 | 用 |
|---|---|
| 卡片、区块、表格、文档区 | **1px 边框**（`--rule`）或只靠表面明度 |
| 浮层（菜单、popover、dialog） | **阴影** + 可选 1px 边 |
| 暗色模式的一切 | **边框 + 表面明度**（暗底上阴影几乎不可见） |
| 控件边界（按钮、输入框） | **1px `--border-control`，必须 ≥3:1** |
| 纯装饰分隔 | 1px `--rule`（**不需要** 3:1） |

### 阴影

**全站只有一个阴影 `--shadow-pop`，只给真正浮起的层。**

- **单一光源**：所有阴影同方向、同比例（垂直偏移 = 水平偏移的 2 倍）。
- **层叠是手法，颜色匹配才是关键**：网上被抄最多的层叠阴影配方用的是
  `rgba(0,0,0,…)` **纯黑**——那正是被点名的 AI tell。
  **把纯黑换成带色相的颜色才是多数人跳过的部分**（令牌里已用 `hsl(210 12% 20%)`）。

- **不要给层叠阴影做动画**（5 层 = 5 倍绘制开销）。
- 暗色下阴影几乎不可见：不透明度要大幅提高（约 40 倍），且**抬升改由表面明度表达**。

### 圆角

只有三档，**圆角值必须承载层级信息**：

| 层级 | 值 |
|---|---|
| 结构容器（卡片、区块、代码块、表格、图片） | `--r-0` = **0** |
| 控件（按钮、输入框、`<kbd>`、标签） | `--r-1` = **3px** |
| 状态点（每屏 ≤1 个） | `--r-full` |

**为什么结构容器是 0**：规范规定当相邻圆角之和超出盒子尺寸时，
浏览器会**按比例缩小所有圆角**——于是"同样"的 `1rem` 卡片在矮元素上看起来不一样。
零圆角让这个问题消失，也让嵌套圆角算术（内 = 外 − 内边距）不再需要。

### 1px 细节

- 分隔线**只画单边**（`border-block-start`），不要上下都画。
- **表格只有横线，没有竖线**；表头下 1 条 `--rule-strong`，行间 1 条 `--rule`。
- **焦点环用 `outline`，不用 `box-shadow`**：
  `outline` 不占空间、不触发重排、跟随 `border-radius`（Chrome 94 / Firefox 88 /
  Safari 16.4 起），且属于 ink overflow **不受 `overflow` 裁剪**；
  `box-shadow` 会被 `overflow: hidden/clip` 裁掉，**且在 Windows 高对比模式下不显示**。
  ```css
  :focus-visible { outline: var(--ring-width) solid var(--ring-color);
                   outline-offset: var(--ring-offset); }
  ```
  高对比模式兜底：`outline: auto 5px Highlight;`
  > **级别说明**：焦点环的尺寸/对比度要求（2 CSS px 周长、前后 3:1）出自
  > **SC 2.4.13，属 AAA**；AA 级的是 **SC 2.4.11**（焦点不得被 sticky 头/脚遮挡）。
  > **我们仍按 AAA 做**——成本只有两行 CSS，键盘用户的实际体验差别很大。
  > 评审时不要把它当成 AA 的达标项来卡。

- **真发丝线**：`border-width: 0.5px` 在整数 DPR≥2 下是真正的 1 设备像素线
  （规范保证，**不会消失**）；DPR=1 下会取整为 1 设备像素。
  但在**分数 DPR**（浏览器缩放、2.65 这类手机屏）下取整方式由浏览器决定。
  → **不要依赖 0.5px 做关键分隔**，1px 是安全默认。

- **禁用 `ridge` / `inset` / `outset` / `groove`**——浏览器对它们的加暗/提亮处理不一致。

### 装饰禁令

- 永不用渐变做装饰背景。
- 永不画假的窗口 chrome（假 URL 栏、假红黄绿点、假 IDE）。
- 永不手绘 SVG 人物/场景；用真实截图。
- **每加一个装饰都问："删掉它，设计会变差吗？"** 答不上来就删。

## 动效

### 时长与缓动

| 场景 | 时长 | 缓动 |
|---|---|---|
| 状态反馈（hover 底色） | `--dur-1` = **100ms** | `--ease-standard` |
| 小 UI（`<details>` 展开、tab 切换） | `--dur-2` = **200ms** | `--ease-out` |
| 浮层出现 | `--dur-3` = **300ms** | `--ease-out`（减速） |
| 浮层离开 | `--dur-exit` = **160ms** | `--ease-in`（加速） |

**上限**：UI 过渡不超过 **300ms**；400ms 已属很慢。
**非对称**：出场取进场的 ~80%；进入减速、离开加速。
**永不用回弹/弹性缓动**（除非是真实的物理拖拽释放）。

### 什么能动

| 该动 | 永不动 |
|---|---|
| hover 底色、focus 环 | **每个区块的 fade-and-slide-up 入场** |
| `<details>` 展开 | 每张卡片的 hover 抬升 |
| 复制按钮的"已复制"反馈 | 视差、滚动劫持、滚动渐显 |
| 浮层出现/消失 | 自动轮播、循环装饰动画 |
| | 用户阅读时任何移动的东西 |
| | 页面背景、滚动时的文字颜色 |

**只动 `transform` 与 `opacity`。** 永不动画
`width` / `height` / `top` / `left` / `margin` / `padding` / `box-shadow`。

**`will-change` 是最后手段**，不是预防措施：只在真的卡顿时加，
动画结束就撤掉；永不整片加在 `<body>` 上。

### 本项目的决策：趋近于零

**不做任何入场动画、不做滚动揭示、不做视差、不做悬停抬升。**

理由：官方反 AI-slop 指导明说"每个区块的 fade-and-slide-up 与每张卡片的 hover 过渡
是通用默认，读起来就是 AI 生成的"；而本站是文档型站点，用户是来读的。

**唯一保留的动效**：hover / focus / `<details>` / 复制反馈（100–200ms）。

### 无障碍

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
```

**"减少动态"不等于"归零"**——最该关的是大面积的缩放与平移，不是 100ms 的底色变化。
本项目设计上就没有位移/缩放，所以这条 media query 几乎是空操作（这是好事）。

**hover 效果必须门控**，否则触屏会出现"卡住的 hover"：
```css
@media (hover: hover) and (pointer: fine) {
  .nav a:hover { background: var(--surface-sunken); }
}
```

## 代码与数据呈现

> **本站的核心说服力来自"真内核、真命令、真输出"，所以代码块的呈现质量直接等于可信度。**

### 语法高亮：颜色越少越好

**代码主题 ≤ 8 个 token 色**（令牌已给 8 个）。
**不设"变量"与"函数调用"专用色**——它们占代码量的 75%，高亮它们等于没高亮。
**不用粗体/斜体做语法区分。** 各 token 色的**明度要不同**，不只是色相不同。

**代码主题通过背景/中性阶与站点关联，不通过把 token 改成品牌色关联。**

**`sorry` 洞用朱批色**（`--code-hole`）——语义正确：未解的洞就是需要关注的东西。

### 终端块

**永不画假窗口 chrome。** 用**排版式边框**：上细线 + 一个文字标签（如
`sokonanoda --json`）+ 下细线。

- 区分**你要输入的命令**与**你会看到的输出**：命令用 `$ ` 前缀并 `user-select: none`
  （前缀不进剪贴板）；输出无前缀、颜色更淡。

- 长行用**横向滚动**（`overflow-x: auto`）而非折行——折行破坏缩进语义。
- `<pre tabindex="0">`，否则键盘用户无法滚动。
- 窄屏把单行控制在 ~60 字符内。

### 行号

短片段（≤15 行，本站绝大多数）**不要行号**；长文件与 diff 要。
有行号时**必须** `user-select: none`（永不进剪贴板）+ `tabular-nums`。

### 复制按钮

位置：代码块右上角，与块内 padding 对齐。**始终可见**（hover-only 在触屏上无等价操作）。
点击目标 ≥ 44×44 px。是 `<button type="button">`，可 Tab 到达，有 `:focus-visible`。
反馈：文案换成"已复制"，2 秒后恢复，**用 `aria-live="polite"` 播报**（不只改颜色）。
降级：非安全上下文下 `navigator.clipboard` 不可用 → 保留可手动复制的路径。

### diff

必须**同时**有四个通道：
1. 行首 `+` / `−` 字符；2. 左侧 3px 色条；3. 背景色；4. 行号列底色。
**永不用颜色作为唯一通道**（红绿是红绿色盲的经典冲突对）。

### 表格

- **用**：≥3 个条目 × ≥2 个可比较属性；只有 1 个属性用列表。
- **不用**：2 列 3 行以下 → 普通文本；**永不为了美观用表格**。
- 表头只有**一行 + 一列**；`<th scope="col">` / `scope="row"`；必须有 `<caption>`。
- 不留空单元格（写"无"）；**不合并单元格**；一格一项。
- **没有竖线**；数字列**右对齐** + `tabular-nums`；长表格 sticky 表头。
- 窄屏横向滚动，**不要把表格拆成卡片**（拆了就失去可比性）。
- 最重要的信息放最前几列；**替用户算好**。

**本站的表格化机会**（当前都散在散文和卡片里）：12 个单元的计数、
三个 harness 的能力差异、`--json` 事件类型。

### 代码呈现禁令

- 永不 `font-variant-ligatures` 默认开启（必须显式 `none` + `"calt" 0`）。
- 永不在代码块内使用中文标点。
- 永不把行号或 `$` 提示符复制进剪贴板。
- 永不在亮页里嵌"带色偏的近黑"代码块（与页面同极性）。
- 永不用假窗口 chrome。
- 永不把代码块做成三套不同的深色。
