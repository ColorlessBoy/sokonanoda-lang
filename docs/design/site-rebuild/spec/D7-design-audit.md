# D7 —— 设计复审（装上前端设计技能后，对**自己**的方案做一次 AI 味审计）

> 背景：用户提出「superpower 啥的 skill 都没装，网页产品做得不够全面，可能是 skill 不够」。
> 于是装了 26 个第三方 agent 技能（`dsh/agent-skills.json`，MIT，见
> `scripts/fetch-agent-skills.py`），然后用其中的 `ai-smell-detector`、`design-system`、
> `frontend-ui-engineering` 回头审**已经写好的设计决定**。
>
> 结论：审出**三处真问题**，全部已改。本文记录判决与理由，供 S23 总验收复查。

## 0. 审计方法

`ai-smell-detector` 的判据不是「某个形状永远错」，而是五个问题：

1. 它服务什么用户/内容/品牌目的？
2. 去掉它，设计会失去意义吗？
3. 它被重复，是因为有系统，还是因为那是省事的默认？
4. 参考里它是**原则**，还是**被抄的时尚线索**？
5. 同一个意图有没有**更具体**的表达？

判决只有四种：`keep` / `adapt` / `replace` / `remove`。

## 1. 逐项判决

| 决定 | 判决 | 理由 |
|---|---|---|
| 方格纸底纹（24px，1.056:1） | **keep** | 产品的材料就是「格子纸上的推导」；它同时让 24px 间距刻度有意义。去掉它，剩下的就只是「细线 + 直角」这个空壳——D1 §方向 已把这条写成边界条件 |
| 结构容器零圆角 | **keep** | 圆角承载层级（结构 0 / 控件 3px / 状态点 full），不是「所有东西同一个圆角」 |
| 发丝线 | **keep** | 它只在**推理横线**上承担语义，每页 2–3 次；不是「每条边界都画线」 |
| 冷调纸面 `#f5f7f9` | **keep** | 刻意避开奶油色——「奶油底 + 高对比衬线大标题 + 暖色点缀」是第 1 类 AI 长相 |
| 两个语义色（绿 / 朱） | **keep** | 都可审计：绿 = 内核真的通过过；朱 = 诊断/更正/诚实的限制。这不是「选了个品牌色」 |
| 编辑器面板用深色机器面 | **keep** | 它就是这个设计的核心隐喻：人写下的文本 ↔ 内核给出的判断 |
| **衬线 display** | **adapt → 已撤** | 见 §2 |
| **页头塞下全部导航** | **replace** | 见 §3 |
| **安装 prompt 用 JS 注入** | **replace** | 见 §4 |
| 三卡功能网格 / 居中 hero / eyebrow 标签 / 链接尾巴 `→` / emoji 图标 | **remove** | D1 已禁；`check-site.py` 与本文一起兜住 |

## 2. 第一处：衬线 display 撤掉，教科书感改由**构件**承担

**原方案**：`--font-display` 用自托管 Source Serif 4（46 KB），理由是「教科书气质」。

**审计过程**（用上面五个问题逐条问）：

- 服务什么目的？——让站点读起来像数学教材。
- 去掉会失去意义吗？——会失去一点，但它**不承重**。
- 是系统还是省事的默认？——是刻意的，不是默认。
- 参考里是原则还是时尚线索？——**"高对比衬线大标题"正是被点名的第 1 类 AI 长相的核心配料**，它是时尚线索。
- 更具体的表达？——**有**。

**判决：adapt。** 教科书感来自**教科书的构件**，不来自衬线：编号小节（`§2.3`）、
页边注、定理/定义/证明块、证明结束的墓碑符、以及推理横线——这些才是数学文本的
**形状**。衬线只是「文学感」的通用符号，任何主题都能贴。

**改动**：
- `--font-display` 现在等于 `--font-ui`（无衬线）；
- 新增构件：`.sec-num`、`.marginalia`、`.statement`（`--definition`/`--theorem`/
  `--lemma`/`--example`）、`.proof`（CSS 画的墓碑符，不用可能缺字的字符）、`.display`；
- **省下 46 KB**：`--font-display` 不再引用 Soko Serif，浏览器不会下载它
  （已在真实浏览器里验证：`document.fonts.check("400 17px 'Soko Serif'") === false`）。
  用户明确说过「快也很重要」，这是白拿的收益；
- 字体文件**保留在** `site/assets/fonts/`，`tokens.css` 里留了一行注释开关，
  设计检查点上如果用户更想要衬线，改一行即可复原。

**注意**：这条只撤掉了 display 层。`--font-mono`（JuliaMono）与 `--font-symbols`
（STIX Two Math 子集）**必须保留**——实测没有任何系统字体覆盖 `⊢`，逐字回退会
静默破坏等宽对齐（R4 §；R1 §3.9）。

## 3. 第二处：28 页规模下，页头导航失效

**原方案**（由 `_partials/header.html` 实现）：页头分 4 组，把**全部**页面链接都列出来，
并明确写下「窄屏用换行而不是横向滚动、也不是 JS 汉堡菜单——390px 下每个链接都可见可点」。

**审计**：这条在 21 页时成立，在**我随后把站点扩到 28 页之后就不成立了**。28 条链接
在 390px 上换行会占掉 6–8 行，把正文顶出首屏——「每个链接都可见」换来的是
「主要内容看不见」。这正是 `responsive-recomposition` 说的：窄屏要**重新编排**，
不是把桌面版压扁。

**判决：replace。** 分两层：

- **页头只留 8 条**最常走的路径（首页 / 为什么 / 内核判卷 / 走查一题 / 语言 /
  课程 / 安装 / 搜索）；
- **页脚承担完整站点地图**，分 5 组（产品 / 功能 / 学习 / 使用与过程），
  **每个页面都带**，所以 28 页里没有一页是孤儿；每组是独立的 `<nav aria-label>`，
  屏幕阅读器可按组跳转；
- 页脚每一项都带 `data-nav`，所以任何页面声明自己的 `data-page` 都不会报错
  （`gen-site-nav.py` 的 `nav_ids` 读的是**所有**块）。

## 4. 第三处：安装 prompt 应该是 HTML，不是 JS

**原方案**：`site/assets/agent-prompt.js`（5 KB）用 JS 把 prompt 文本注入 `<pre>`。

**审计**：内容是**正文**，却要等 JS 才有。`frontend-implementation` 的原则是
「内容在 HTML 里，JS 只做增强」——无 JS 时这一页的核心内容直接消失。

**判决：replace。** prompt 文本改成 `_partials/agent-prompt-{zh,en}.html`，
用与导航**同一套**注入机制（`gen-site-nav.py` 的块）写进页面，
`check-site.py` 逐字校验。收益：内容无 JS 可读、可被搜索引擎与 `llms.txt` 收录、
少一个 5 KB 的 JS 文件、且仍然只有**一处**源。

> 这一项**尚未实施**：需要给 `gen-site-nav.py` 的 `BLOCKS` 加「可选块」语义
> （目前每个块都要求每页都有标记）。排进 S29，与其余站点文件同批。

## 5. 顺带补出的内容缺口

同一次复审还发现**七处内容缺口**（详见 D2 §1.1）：搜索、与 Lean 4/Coq/Agda 的对照页、
术语表、常见问题（C3 §7 已有 24 行安装痛点表却无处安放）、版本历史、404、
`sitemap.xml`/`robots.txt`/`llms.txt`。每一项都过了「它服务什么目的」这一问，
没有为凑数而加的页。

## 6. S23 总验收时用这份清单复查

- [ ] 全站 grep：没有居中 hero、没有 eyebrow 标签、没有链接尾巴 `→`、没有 emoji 图标
- [ ] 每个强调色元素都能回答「背后有什么真实判定」；绿与朱不同时出现在一个元素上
- [ ] 方格纸**可见**（1.056:1），且没有铺在任何文本容器底下
- [ ] 结构容器圆角 = 0；控件 = 3px；只有状态点用 full
- [ ] 区块级垂直间距都是 24 的整数倍
- [ ] 每页 `.turnstile` 出现 2–3 次，位置固定
- [ ] 390px 下无横向溢出；正文不被导航顶出首屏
- [ ] 关闭 JS 后每页仍完整可读可导航（含安装 prompt 文本）
- [ ] 把成品截图与「近黑底 + 荧光绿」和「报纸密排」两个印象对比——若一眼像其中
      任何一个，就是漂了（D1 §方向 的边界条件）
