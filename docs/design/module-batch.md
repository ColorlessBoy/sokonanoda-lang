# 设计：模块级批量编译（`plan_module(root)`，阶段 C / T-C1，2026-09-25）

> **要解决的**（E2 §0.2 阶段 C）：`build <dir>` 今天对**每个文件**各编一遍**完整闭包**
> ⇒ O(文件数 × 闭包)。基线 **`build courses/set-theory` = 146.07s / 35 文件**。
> 目标：把模块根下**全部**文件当**一批**编一次，共享的部分只算一次。

## 1. 现状（都有出处）

| 层 | 今天有什么 |
|---|---|
| 编译层 | **已经支持多单元**：`SourceUnit { name, path, file }`、`unit_ranges`（扁平命令序按单元切区间）、`split_report`（把报告切回每个单元并把 `cmd` 下标**重基**）、唯一入口 `compile_all_units(units, options) -> (CompileOutput, Vec<DocumentReport>)`（`crates/front/src/compile/units.rs:113`） |
| 项目层 | `plan_project(entry)` **只加载入口的闭包**（拓扑序、入口在最后），然后 `compile_all_units`（`crates/front/src/project/mod.rs:326`）；`build <dir>` 对每个文件各调一次 ⇒ 共享依赖被重复 elaborate |
| 没有的 | **规划侧**：把"模块根下的全部文件"组装成一批、去重、定序、按文件切报告 —— 这就是本阶段要加的 |

`run(units, options, collect)` 的第三个参数是 **`collect`（要不要收集事件流）**，不是
"入口标志"（`check/mod.rs:446`）⇒ 平坦批编**没有**针对"最后一个单元"的特例 ✓。

## 2. 契约：`plan_module(root, options) -> ModulePlan`

```
ModulePlan {
    root: PathBuf,                        // 模块根（绝对）
    units: Vec<PlannedUnit>,              // **拓扑序**，去重后每个文件恰好一个单元
    order: Vec<PathBuf>,                  // units 的路径（同序，便于对账）
}
PlannedUnit { path: PathBuf, name: String, digest: String }   // digest = 该文件**自己闭包**的摘要
ModuleReport { per_file: BTreeMap<PathBuf, FileReport> }      // FileReport = 今天的 DocumentReport + 归因
```

### 2.1 文件枚举（**红线**）
* 递归收集 `*.sokonanoda`，按路径**排序**（确定性）；
* **必须跳过产物目录 `.sokonanoda/`** ✗ —— `build` 今天的 `collect_files`
  （`crates/cli/src/build.rs:172-191`）**不跳隐藏目录**，而产物目录现在就在模块根下；
  本项目的一贯红线是"产物的扩展名绝不是 `.sokonanoda`"（T-B4 §3.3），枚举这一侧再加一道
  过滤，两道一起保证"产物不会被当成源文件"；
* 与今天一致：**清单（`sokonanoda.toml`）不参与枚举**，模块根由调用方给出（`build <dir>`
  的每个目录各自成批；`--root`/`--no-project` 语义不变）。

### 2.2 拓扑序与去重
* 取**所有文件各自闭包的并集**（按路径去重：一个文件既可能是入口、也可能是别人的依赖，
  批里只出现一次 —— 这就是省下来的那部分）；
* 排序：**依赖先于依赖者**；平手按**路径**（确定性；不依赖文件系统顺序）；
* 环：与 `plan_project` 同一条口径（加载期诊断 `import-cycle`），**不**在批里另造一套。

### 2.3 `ok(file)` 的语义（**等价性契约**）
对根下每个文件 `F`：

> `ModuleReport.per_file[F]` 必须与"**以 `F` 为入口、按今天的路径单独编一次**"得到的报告
> **逐项相同**：声明状态（`checked`/`failed`/`blocked`）、诊断集合（code + 位置 + 消息）、
> `decl.checked` / `exercise.open` 事件序列与计数。

单文件/单入口路径**一行不改**（A1 纪律：`import`-free 文件零项目开销）。

### 2.4 失败隔离
一个文件 parse/compile 失败**不许**拖垮批里其它文件：报告按文件切分，失败只影响该文件
（与今天"每个文件各自编"的隔离度一致）；加载期失败（缺依赖/环）沿用 `ProjectDiagnostic`
的归因，不新增事件类型。

### 2.5 缓存与产物（与 T-C6 / `.sokonanoda/` 衔接）
* 批的缓存键 = **排序后**每个文件的 `(路径, 源文本, 依赖边)` + prelude 模式 + 编译器版本
  + build stamp（与今天项目摘要同一套料，只是从"入口闭包"扩成"整根的并集"）；
* 命中 ⇒ 直接回放逐文件报告；未命中 ⇒ 编一次并写一份**模块级条目**（放
  `<模块根>/.sokonanoda/`，格式沿用既有条目，见 T-C6）；
* 逐文件的旧条目**仍然有效**（读顺序：模块级 → 逐文件 → 全局）⇒ 升级平滑。

## 3. 等价性的**已知风险**（T-C3 必须量出来）
平坦命令序意味着 `F` 的**环境**包含**它前面所有单元**——包括它**没有 import** 的模块。
这与"以 `F` 为入口单独编"（环境 = prelude + `F` 的传递依赖）**不一定相同**，可能出现的差异：

1. **名字解析/遮蔽**：两个文件声明了同名顶层名字时，平坦序里后来的那个会遮蔽前者；
   单独编时各自只看得到自己闭包里的那个 ⇒ 报告可能不同；
2. **重复声明类诊断**：无关模块带来的同名声明可能触发"重复定义"诊断；
3. **未使用/可疑声明类警告**：环境变大后，某些"从未被引用"的判定可能变化。

**刹车（E2 §3 已写死）**：T-C3 的等价性判据**不过** ⇒ **不接 `build`** ✗，把 API 与判据
留在树上（惰性、零成本），把差异逐条记进本文；阶段 C 只交"API + 判据 + 差异记录"。

## 4. 非目标（本阶段不做）
* 不做跨文件增量（改一个文件只重编它）——那是 K2/阶段 D 的事；
* 不做并行编译（批内顺序执行；并行要另证判定不变）；
* 不改单文件路径、不改 `plan_project` 的既有调用方语义；
* 不引入"已编译环境导入"（v1 边界，`compile-cache.md:86-90`）。

## 5. 接线（T-C4 / T-C5）

T-C5 量出收益并**默认打开**（数字进 `docs/perf/ledger.jsonl`）。
