# `soko/goals` 载荷瘦身（设计 · 2026-10-09）

> 见 `docs/notes/PLAN-align-lean4.md`。

## 1. 读数（实测，先量后动 ✓）

| 项 | 值 | 怎么量的 |
|---|---|---|
| `soko/goals` 请求往返 | **5.9ms** | `PERF goals-wallclock`（真子进程 ✓） |
| 其中 **front** `goals(false)` | **2.16ms** | `PERF goals-cost-course`（真 unit08 文本、项目模式 ✓） |
| 其中 **LSP 层**（相减） | **3.7ms** | — |
| **响应体积** | **91 361 B** | `PERF goals-lsp`（文档本身才 24 019 B ⇒ **3.8×** ✗） |
| 往返底噪 / 内核探针 | 0.0ms / ±0.2ms | `PERF rpc-floor` / 开关 A-B |

⇒ LSP 那 3.7ms 的**主因是载荷**：每条声明的 `ty_runs` / `goal_runs` / `value_runs` 把
**每个 token** 都做成一条 `RunInfo`（`{text, kind, start, end}`）⇒ 91KB 要序列化 + 客户端解析**每次**。
**对照 Lean**：`$/lean/plainGoal` **只回目标文本** ✓ ⇒ 这一格的差距是**协议形状**，不是编译慢 ✓。

* **消费者**：`editor/vscode/`（真正读 runs 的人 ✓）· `skills/`（写协议的说明 ✓）·
  `docs/protocol.md`（**契约唯一权威** ✓）⇒ **必须同一轮同步** ✓。
* **红线**：`--json` 事件流与判卷**不受影响** ✓（本设计只动 `soko/goals` 这一条自定义请求的**可选**字段 ✓）。
* **不许**删旧字段、不许改语义 ✗ —— 要下线走**弃用流程**（先文档标注、后大版本删 ✓）。

## 3.1 ⚠ 先量了候选 A：**压缩比只有 2.6×**（2026-10-09 实测，修正 §3 的估计）

`crates/front/tests/goals_payload_shape.rs`（真 unit08、项目模式）实读：

```
现状 decls≈89 515B（文档 text≈24 019B）· runs JSON≈55 433B
⇒ 稀疏后≈21 207B（压缩比 2.6×、省 34 226B）· 预计响应 113 534B → 79 308B
```

⇒ **§3 里"91KB → 5–10KB"的估计是错的** ✗（实际只到 **~79KB**，即 −30% ✗）。两个原因：
① runs 的 kind **没有想象中那么连续**（2.6× 而非 5–10×）；② 响应里**还有 ~34KB 不是 runs**
（每条声明的 `ty`/`value`/`goal` **文本** + 名字/kind/span ✓，这些是**必要**的 ✓）。

⇒ **A 单独不够**：全做（A + B 按需）大约把 91KB 砍到 ~50KB ⇒ LSP 那 3.7ms 乐观也就降到 ~2.5ms
⇒ goal 从 5.9ms 到 ~4.7ms，**仍高于 Lean 的 3.1ms** ✗。
⚠ **结论**：**载荷瘦身是有界收益，不是"打平 Lean"的那一刀** ✗ —— 它仍是好卫生（−30% 客户端解析 ✓），
但**不许**把它当成"goal 口径反超"的路径 ✗。真正对齐 Lean 的是**它的机制**：`plainGoal` 直接读
**该命令的快照**、**不产出**逐 token 着色数据 ✓（我们的 T2-B 已经有命令级快照 ✓ —— 用它对 goal
查询**只答目标**、把 runs 留给按需索取 = 本设计的 B **加上** T2-B 的读取面 ✓）。

## 3. 候选编码（择一，实现前先各量一次 ✓）

| 候选 | 形状 | 体积估计 | 风险 |
|---|---|---|---|
| **A. 稀疏 runs** | 只发 **kind 变更点**：`[{start, kind, len?}, …]` ⇒ 客户端线形展开 ✓ | 91KB → **~5–10KB** | 客户端要改解析 ✓；等价性需判据 |
| **B. 按需索取** | 请求加 `runs: "none" \| "all"`（缺省 `all` ✓ 旧行为不变 ✓） | 视客户端而定 ⇒ **~24KB**（只剩 `text`） | 扩展要发两次请求或自己再要一次 ✓ |
| **C. 表化** | runs 去重成**字典 + 下标**（kind 与 text 高度重复 ✓） | ~10–20KB | 解析复杂度上升 ✓ |

**倾向**：先量 A 的真实压缩比与等价成本 ✓（`runs` 的 kind 段本来就连续 ✓ ⇒ 稀疏化天然合适 ✓）。
