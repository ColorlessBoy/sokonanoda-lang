## 4. 纪律与踩过的坑（照抄，别重踩）

0. ⭐ **推送节奏**：一次 CI **median 24.6 分**，而**本机同一条活 217 秒 ⇒ 快约 6 倍**。**四条**：
   **(a) 中间环节不推 CI** · **(b) 攒到发版点一次推**（P1-d + Q1 合推）· **(c) 推完不许 `--watch`
   盯着等**（等的时候 agent 完全停工）· **(d) 不许连推**（`cancel-in-progress: true` ⇒ 后推的顶掉
   前一轮）。⚠ 2026-09-29 那轮 P1-a/b **违反了 (a)(b)**，白跑数轮 ⇒ 别重犯。
   ⚠ **推送前三步**：`git fetch` → `gh run list`（在飞就别推）→ `pull --rebase` 再推 ——
   CI 的 `e2e ledger (commit back on main)` job **每轮结束都往 main 回写提交**，不 fetch 必被
   non-fast-forward 拒（那轮踩了三次）。
1. **口径**：报数先贴 **failed + 三条计数**（`JUDGE_PREFIX runs/bytes`、`hits/misses`、judge pass 数）
   **再谈墙钟**；计数减半 ≠ 墙钟同比；**<5% 差不许当结论**。
2. **两条红线**：`--json` **剔除 `build.tick`**（它是按设计随墙钟变的心跳）后**逐字节不变**；
   **反向判据**（依赖/前缀真变 ⇒ 必须重算）必须有**实测**。
3. **"只做未命中"不许破**：就地路径对**每一次**调用生效会把十几万次廉价命中换成 ~1ms/次 ✗
   （实测 400s 跑不完）⇒ 新接线点先问"这一趟在慢路上原本花不花前缀钱"。
4. **判据不许空转**：每个新接线点的测试都要断言"**就地路径真被走到**"（`INPLACE_USED` 增长）；
   夹具没踩到接线点时它**当场判红**。凡写「必红 / 强制 / 例行」的守卫，**逐条核对它真的拦**
   （`continue-on-error` / `|| true` / 守卫的输入是否真的存在）。
5. **三个实测坑**（附七 §4 有全文）：① pp 必须与 `kernel_phase:199` 同档设 `proofs=true`，
   且 `quiet_catch` 要包在 `with_env` **内层**；② 判定查询文本要用 `render_expr`（**不是** pp
   回读入口，记法会解析失败）；③ 就地路径**不解析**（源 AST 直接造项），否则每问解析 46KB ✗。
6. **记法路径守卫**的指纹 = **去空白后的整行** ⇒ rustfmt 把闭包折成一行会变成"新增绕过"；
