## 正文

```markdown
学形式化证明，第一道坎往往不是数学，而是工具链。

装 Lean、配 elan、拉 mathlib、搞明白 Lake 和 `import`，再花半天和编辑器插件搏斗——
等真正写下第一个 `theorem`，最初的热情已经消耗得差不多了。对已经决定投入的人，
这些只是入门成本；对只是想「试试看形式化证明是什么样」的人，它足以让人放弃。

Sokonanoda 是我对这个问题的回答：一个装个 VS Code 插件就能开始写的证明语言。
它不试图替代 Lean，目标只是把「第一小时」的门槛降到接近零。

## 它长什么样

打开一个 `.sokonanoda` 课程文件，把光标停在 `sorry` 上，右侧面板会显示内核实时
算出的目标：

    α : Type
    A B : Set α
    ⊢ A ∩ B = B ∩ A

把 `sorry` 换成证明，保存，声明会由完整的内核判定通过或拒绝。目标面板不是
「根据语法猜的」，而是内核 `query state` 的输出；判卷也不是正则或大模型打分，
而是把补完的声明交给内核，看它是 `decl.checked` 还是留下 `exercise.open`。

## 三个设计决定

**一、内核判卷，而不是文本匹配。**
证明助手的价值在于「它真的检查了」。Sokonanoda 的底层是一个 Lean 4 兼容内核
（Rust 实现），上层才是受限的教学方言。这带来两个直接结果：错的证明不会因为
「看起来像」而通过；同一份内核输出同时驱动编辑器、CLI 的 `--json` 和课程门禁，
不会出现「编辑器说对、判卷说错」的分裂。

**二、教学子集，而不是 Lean 复刻。**
语法是 Lean 4 的一个子集：课程需要什么就实现什么，不追求 tactic 全覆盖，也没有
mathlib。这是一个有意的取舍——子集让错误信息可以写得像教材，让编译保持快，
也让「学完能迁移到 Lean」成为目标而不是负担。代价是它不能直接拿来做研究级形式化。

**三、零工具链。**
VS Code 扩展按平台打包了 LSP 和 CLI（macOS、Linux、Windows，共 8 个平台包），
安装后不需要 Lean、不需要 Rust，也不需要联网下载。对课堂和第一次接触的人，
「装一个插件」比「配一套工具链」现实得多。

## 课程

三门课，298 个单元、2,022 道练习，全部带内核验证过的解答：

- 入门逻辑：11 个单元，从命题证明到归纳、量词、模块；有英文镜像
- 集合论：112 个单元，从隶属、外延性到序数、基数、选择公理和商构造
- 实分析：175 个单元，从 ℤ、ℚ、ℝ 的构造到序列、连续、导数和微积分基本定理

多数练习配有 `soko:hint` 提示阶梯，只给触发条件和该用的引理名，不给完整答案（少量旧题还没有提示）。
另有 409 道选择题 / 195 个知识点，供复习和调度使用。

## 它不是什么

- 不是 Lean 的替代品：没有 mathlib，不能 import Lean 文件，tactic 只覆盖课程用到的那些
- 不做研究级形式化：目标读者是学习者、教师和课程作业
- 课程中文优先：入门课有英文镜像，集合论和实分析暂时没有
- 内核不是「已证明正确」的：它通过 Lean Kernel Arena 的语料（135/138 accept、
  90/92 reject，3 个性能超时、2 个 known unsupported），但和所有内核一样，
  它是被测试和审计的，不是被形式化验证的

## 适合谁

- 想学形式化证明、但被 Lean 的安装和工具链挡在门外的人
- 需要给学生在课堂上布置「能自动判卷的证明练习」的老师
- 想看看「内核判卷 + 教学子集」这套组合怎么落地的开发者

## 怎么开始

官网（中英双语）：https://colorlessboy.github.io/sokonanoda-lang/
VS Code Marketplace 搜 `sokonanoda`。
代码与课程（Apache-2.0）：https://github.com/ColorlessBoy/sokonanoda-lang

如果试了，欢迎告诉我卡在哪一步。对教学设计来说，「哪一步让人停下来」比
「功能多不多」更有用。
```
