# cases

对假设做情形分析，每个构造子一个分支。

## 怎么用

写法是 `cases <假设名> with`，后面一个构造子一个分支，分支里拿到这个构造子的字段：

```sokonanoda
example (a b : Prop) (h : a ∧ b) : b := by
  cases h with
  | intro ha hb => exact hb
```

`h : a ∧ b` 只有一个构造子 `And.intro`，所以这里只有一个分支。分支名写**短名**
`intro`（也可以写全 `And.intro`），后面跟这个构造子带的字段名。真的分成好几支的是
`∨` 这样的假设，分支名写 `inl` / `inr`：

```sokonanoda
example (a b : Prop) (h : a ∨ b) : b ∨ a := by
  cases h with
  | inl ha =>
      right
      exact ha
  | inr hb =>
      left
      exact hb
```

`h : a ∨ b` 分成两支。`inl ha` 那支拿到 `ha : a`，目标仍是 `b ∨ a`：用 `right` 挑
右边，再交 `ha`。`inr hb` 那支对称。分支里和其他地方一样，可以写好几条 tactic，
每条只管这一支。

## 什么时候用

**适用**：手里有一条归纳类型的假设（`a ∧ b`、`a ∨ b` 这种），你想按它的构造子分成
几种情况分别证。

**不适用**：要拆的是**目标** —— 那用 `constructor`（`∧`）或 `left`/`right`（`∨`）。
另外，目标里提到了这条假设时 `cases` 今天不支持（见下表第五条）。

## 内核在背后判什么

`cases` 自己不做推理：它把整块**降低成一个 `match` 项** —— 每条分支里那串 tactic
各自组装成一条证明项，递归与归约交给语言既有的 `match` 路径（内核的 iota 归约）。
换句话说，`cases` 是 `match` 的 tactic 版：判定同一套，只是让你在每条分支里写
tactic，而不是写项。

被消去的那条假设必须是一个**局部假设名**（`cases h` 这样写，`cases And.left h`
不行），分支拿到的名字由你取，个数必须与构造子的字段数一样多。

## 常见错误与出路

| 你看到的 | 意思是 | 下一步 |
|---|---|---|
| `` `cases` 的被消去项必须是一个**局部假设名**（例如 `cases h`） `` | `cases` 后面写的是一个复合项，不是名字 | 先用 `have` 把这个项记成一条假设，再 `cases` 它 |
| `` `cases` 读不到 `h` 的类型 `` | 这个名字在当前上下文里查不到类型 | 检查拼写；确认它是前面 `intro`/`have` 引入的假设名 |
| `` `cases` 的被消去项不是归纳类型的值：`Prop → Prop` `` | 这条假设的类型连头都不是一个类型构造子（这里是箭头） | 换一条归纳类型的假设；箭头类型先用 `intro` 拆开 |
| `` `cases` 只支持**归纳类型**，但 `h : True` 的头 `True` 不在归纳表里 `` | 类型有头，但那个头不是已声明的归纳 | 看看这条假设装的到底是什么（公理、定义还是别的）；它可能不该被 `cases` |
| `` `cases a` 暂不支持**目标依赖该假设**的情形（dependent elimination）：目标 `a` 里提到了 `a` `` | 目标里提到了这条假设，消去它会让目标失去意思 | 换个不依赖它的思路；或者先把目标里依赖它的那部分处理掉 |
| `` `cases` 分支 `intro` 需要 2 个假设名（构造子有 2 个字段），实际给了 1 个 `` | 分支名个数与构造子的字段数对不上 | 数一下构造子的字段：`And.intro` 两个、`Or.inl` 一个；名字随便取，个数要对 |
