# have

在证明中间先证一条 `h : T`，当前目标不变。

## 怎么用

`have` 给一个项起名字。写法是 `have <名字> : <类型> := <值>`，名字、类型、值三样
都要写。类型不能省：本语言不做隐式推断，少了它就没法判「这个值的类型对不对」。

值有两种写法。第一种是一个现成的项，通常来自某条假设或某个已经证过的结论：

```sokonanoda
example (a b : Prop) (ha : a) (hb : b) : a ∧ b := by
  have h : a := ha
  exact And.intro h hb
```

`have h : a := ha` 把假设 `ha` 记成名字 `h`，类型写明是 `a`。后面 `And.intro h hb`
就按名字引用它。同一个名字可以连着起好几个，互不干扰。

第二种是 `:= by` 开头，后面写一小段 tactic，现场把值证出来：

```sokonanoda
example (a b : Prop) (ha : a) (hb : b) : a ∧ b := by
  have h : a ∧ b := by
    exact And.intro ha hb
  exact h
```

缩进决定这段 `by` 到哪里结束：不超过 `have` 那一列的 tactic 属于外层。这里
`exact h` 在外层，因为它的缩进比 `have` 浅。

## 什么时候用

**适用**：一个项要反复用，或者你想把长证明切成几段、每段先给个名字。名字一取，
后面每一步的意图都写在名字里，目标状态也不会被一长串项撑满。

**不适用**：只想直接把目标填上时，用 `exact`；想把函数结论对上目标、让它的前提
变成新目标时，用 `apply`。`have` 自己不推进目标，所以它不能单独结束一个证明。

## 内核在背后判什么

`have` 降低成一次函数应用：整个证明被组装成 `(fun (h : T) => 剩下的证明) 值`。
函数类型是 `T → 目标`，所以值这一位需要的正是 `T`，剩下的证明拿到的上下文里多了
一条 `h : T`。

值算完之后，`have` **立刻**把它交给内核判一次，判的是「值的类型与 `T` 定义相等」
（defeq，与 `exact` 同一条通道）。相等就继续；不等就把错误报在 `have` 这一行，
而不是等整个证明组装完、由内核在一个位置很远的应用处报错。所以你在屏幕上看到的
是 `have` 那一行被标红。

判过之后目标一个字不动 —— 变的只是上下文多了一条假设。什么时候用它、用它做
什么，都是后面那些 tactic 的事。

## 常见错误与出路

| 你看到的 | 意思是 | 下一步 |
|---|---|---|
| `` `have h` 的值类型不匹配：期望 `False`，实际是 `True` `` | 名字后面写的类型与值的类型定义不相等 | 对一下两边：要么改类型标注，要么换一个值。想故意留个缺口，把值写成 `sorry`（见 [`sorry`](sorry.md)） |
| `` `have h` 判定失败：洞不在可填写的位置 `` | 值里的洞落在一个没法填的位置，内核拒绝 | 检查那个洞的上下文：换个位置，或者先证出真正缺的那一块再 `have` |

「期望/实际」后面那两段是内核打印出来的类型，逐例不同：上面第一行的例子里，
`have h : False := True.intro` 的值是 `True.intro`，类型是 `True`，与写的 `False`
对不上，内核就这么报。第二行里的名字 `h` 就是你写的那一个。
