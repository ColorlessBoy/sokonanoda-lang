# left

选目标归纳的第一个构造子（`A ∨ B` 上就是左边 `A`）。

## 怎么用

`left` 不带参数。目标是 `A ∨ B` 时它挑第一个构造子 `Or.inl`，目标从 `A ∨ B` 变成
`A`，接下来要证的就是左边那半。

```sokonanoda
example (a b : Prop) (ha : a) : a ∨ b := by
  left
  exact ha
```

## 什么时候用

**适用**：目标是 `A ∨ B`，而且你能证左边 `A`。写完 `left`，目标就只剩 `A`。

**不适用**：你要证的是右边。写 `left` 它会选中左边，目标变成 `A`，后面多半证不
出来 —— 这时用 `right`。

## 内核在背后判什么

`left` 与 `constructor` 在本语言里是**同一台机器**：都取目标归纳的第 0 个构造子，
再走 `apply` 的判定。`Or` 的第 0 个构造子是 `Or.inl`，所以 `left` 之后目标就是
左边那半。它**不看**左边是不是真的可证，只按构造子的顺序取。

也正因为是同一台机器，归纳只有一个构造子时 `left` 照样成功：它把那个构造子应用
上去，字段留成目标。`∧` 就是这种情形：

```sokonanoda
example (a b : Prop) (ha : a) (hb : b) : a ∧ b := by
  left
  exact ha
  exact hb
```

这段能过，但读起来绕。目标是 `∧` 时直接写 `constructor` 更清楚，`left` 这个名字是
为 `∨` 准备的。

## 常见错误与出路

| 你看到的 | 意思是 | 下一步 |
|---|---|---|
| `` `left` 需要目标是**归纳类型**，但当前目标的头 `a` 不在归纳表里（它可能是公理、定义，或者是一个函数目标——先 `intro` 拆开试试） `` | 目标（展开之后）不是归纳类型 | 是箭头就先 `intro`；目标是 `∃ x, p x` 用 `use`；先看清目标的头是什么 |
| `` `exact` 类型不匹配：期望 `a`，实际是 `b` `` | 你已经站在左边那个目标上，但手上只有右边的证明 | 你要给的是右边 ⇒ 把 `left` 换成 `right` |
