# constructor

按目标取第一个构造子，它的参数变成新目标。

## 怎么用

`constructor` 不带参数。目标是归纳类型时，它取出这个归纳里**声明顺序的第一个**
构造子，构造子的字段按顺序变成新的子目标。

```sokonanoda
example (a b : Prop) (ha : a) (hb : b) : a ∧ b := by
  constructor
  exact ha
  exact hb
```

`∧` 的第一个构造子是 `And.intro`，它有两个字段 `a` 和 `b`。`constructor` 之后目标
变成两个，按顺序一句 `exact` 收一个。手写 `apply And.intro` 是同一个效果，
`constructor` 只是省掉了构造子的名字。

## 什么时候用

**适用**：目标是归纳类型，而且它的**第一个**构造子正是你要交的那个。`∧` 是最常见
的一例：`And.intro` 的结论就是整个目标。

**不适用**：第一个构造子不是你要的。目标是 `A ∨ B` 而你要给右边那半时，用 `right`
取第二个构造子。目标还是箭头（`→`）或全称量化（`∀`）时 `constructor` 也用不上，
先用 `intro` 把目标拆开。

## 内核在背后判什么

`constructor` 做的就是 `apply <Ind>.<第一个构造子>`：先看目标的头是哪个归纳，从
归纳表里按声明顺序取出第 0 个构造子，再走 `apply` 的那套判定 —— 构造子的结论与
目标是否**定义相等**由内核说了算。目标写的是别的形状也不要紧，两边都会先做定义
展开，所以 `↔`（它在定义上就是 `And`）上也照样能用：

```sokonanoda
example (a b : Prop) (hab : a → b) (hba : b → a) : a ↔ b := by
  constructor
  exact hab
  exact hba
```

有一件事要记住：它**不挑"能证的那个"**，永远取第一个。只有半边可证时，它照样把
你放在第一个构造子的目标上，等后面那一步报错才暴露出来 —— 下表第二条就是那个
现场。

## 常见错误与出路

| 你看到的 | 意思是 | 下一步 |
|---|---|---|
| `` `constructor` 需要目标是**归纳类型**，但当前目标的头 `a` 不在归纳表里（它可能是公理、定义，或者是一个函数目标——先 `intro` 拆开试试） `` | 目标（展开之后）不是归纳类型 | 是箭头就先 `intro`；目标是 `∨` 就用 `left`/`right`；先看清目标的形状再选 tactic |
| `` `exact` 类型不匹配：期望 `a`，实际是 `b` `` | `constructor` 取了第一个构造子，它要的是左边 `a`，而你手上只有 `b` | 你要给的是右边 ⇒ 把 `constructor` 换成 `right` |
