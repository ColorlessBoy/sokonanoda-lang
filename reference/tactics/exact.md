# exact

交出证明项 `e`；内核判 `e` 的类型与当前目标是否定义相等（defeq）。

## 怎么用

写法是 `exact <项>`。项可以是假设名、带上实参的引理、一个函数本身，甚至一整段
`match`：只要是「一个能证明当前目标的项」就行。

```sokonanoda
example (a b : Prop) (h : a ∧ b) : b := by
  exact And.right h
```

`And.right h` 取出 `h` 的右半，它的类型正好是 `b`，所以一句就结束。

`exact` 认的是**定义相等**（defeq），不是「字面一样」。下面这个例子里，目标与项
写出来的形状不同，内核照样收：

```sokonanoda
def MyAnd (a b : Prop) : Prop := a ∧ b

example (a b : Prop) (h : a ∧ b) : MyAnd a b := by
  exact h

example (a : Prop) : a → a := by
  exact fun (ha : a) => ha
```

第一个例子里 `MyAnd a b` 展开一层就是 `a ∧ b`；第二个例子直接交一个函数，
它就是 `a → a` 的证明。

## 什么时候用

**适用**：你手上已经有完整的证明项（一条假设，或「引理 + 实参」），只差把它交给
内核。

**不适用**：目标还是复合形状、而你手上没有整体证明的时候。目标是 `a ∧ b` 就先
`constructor` 拆成两个，目标是 `∃ x, p x` 就先 `use w` 交出证人；拆开之后每一块
再用 `exact` 收尾。

## 内核在背后判什么

`exact` 把项 `e` 连同当前目标一起交给内核：内核算出 `e` 的类型，再判这个类型与
目标是否 **defeq**（定义相等）。判等由内核完成，`exact` 自己不做任何文本比对。

判等失败时，报错里的「期望」是目标类型、「实际」是 `e` 的类型，两段都由内核打印
出来，所以每个例子里看到的文字都不一样。

## 常见错误与出路

| 你看到的 | 意思是 | 下一步 |
|---|---|---|
| `` `exact` 类型不匹配：期望 `a`，实际是 `Prop` `` | 交出去的项类型与目标不一致（这里是把 `Prop` 本身当成了 `a` 的证明） | 先用 `#check` 看那条项到底是什么类型；差实参就补上，形状不对就先拆目标 |
