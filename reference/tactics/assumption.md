# assumption

在已有假设里找一条与目标定义相等的，直接结束当前目标。

## 怎么用

`assumption` 不带参数：它自己在当前上下文的假设里找。找到就直接结束目标，找不到
就报错。

```sokonanoda
example (a : Prop) : a → a := by
  intro ha
  assumption
```

`intro ha` 引入的假设 `ha : a` 与目标 `a` 相同，`assumption` 收尾。好处是名字不用
写；也正因为名字不用写，它今天最容易让人踩坑（见下一节）。

## 什么时候用

**适用**：目标恰好就是某条假设，而且你懒得（或不想）写它的名字。

**不适用**：要用的那条假设**不是最新的一条**时（今天一定会失败，见下一节）；或者
目标是复合形状、需要你拼出来的时候。这两种情况都改用 `exact` 并点名那条假设。

## 内核在背后判什么

⚠ **下面是今天真实的行为，不是 Lean 4 的行为**，写在这里免得你按 Lean 的印象排查。

`assumption` 只检查**最新**那条假设，也就是上下文中最后引入的那一条：它把这条
假设的类型交给内核判一次 defeq（与 `exact` 同一条通道），相等就结束目标，不等就报
「没有找到」。**这是一个已知缺陷（台账 `G-110`），尚未修复**：Lean 4 的 `assumption` 会**从最新往旧
搜遍整个局部上下文**，我们这边只看了第一条。后果是，需要的那条假设后面还跟着别的
假设时，`assumption` 会报找不到，而在**同一个上下文**里 `exact ha` 完全能过。

所以要用的假设必须**正好是最新的一条**。下面这个例子里，`ha` 是 `intro` 刚引入的：

```sokonanoda
example (a b : Prop) (hb : b) : a → a := by
  intro ha
  assumption
```

## 常见错误与出路

| 你看到的 | 意思是 | 下一步 |
|---|---|---|
| `` `assumption` 没有找到类型与目标一致的假设 `` | 最新那条假设的类型与目标不等；你要的那条可能在更早的位置，今天它不会被检查 | ① 把要用的假设放到最后（例如调整绑元的顺序，或用 `intro` 最后引入它）；② 直接用 `exact` 点名那条假设 |

## 相关

- [`intro`](intro.md) —— `intro` 引入的假设正好是最新的一条
