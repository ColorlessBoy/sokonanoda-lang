# sorry

占位：目标保持开放。练习没做完的合法状态，不是错误。

## 怎么用

`sorry` 不带参数，写在需要证明的地方就行。它表示「这里先空着」：

```sokonanoda
example (a : Prop) : a := by
  sorry
```

这一段检查不会失败。工具把这条声明算成**练习未完成**（open exercise），而不是算成
错误 —— 你随时可以回来接着写。

**这里有一个容易看错的区别**：`sorry` 写在 `by` 块里，它填的是**当前那个目标**；
写在项的位置（`:=` 右边、或者某个实参的位置），它填的是**那一位**。两种写法的报错
行为不一样，见下一节。

## 什么时候用

**适用**：一道题写到一半，想先编译看看别处有没有错；或者想先摆出证明的骨架，
把几块难的地方留空，之后再一块块补上。

**不适用**：拿它当「先这样交上去」的挡箭牌。它确实能让检查通过，但声明还是未完成，
该证的命题你仍然没证。另外，一个证明已经写完了就别再留 `sorry`：那行是多余的，
会得到下面那条硬错误。

## 内核在背后判什么

`sorry` **什么都不做**。它不改变目标、不引入假设，也不给内核任何东西判 —— 它只是
让当前目标保持开放。内核那边，含洞的声明走「未完成」这条通道，所以它是合法状态，
不是错误。

真正要分清的是两种情况，它们的学习含义完全相反：

- **真缺口**：这个洞**有位置可填**，也就是那里确实需要一块证明。声明未完成，
  补上内容就能通过。
- **多余的 `sorry`**：证明其实已经完整，`sorry` 落在了一个没人需要的位置上。
  检查照样通过、声明照样是未完成，但真相是你的证明早就证完了，多出来的那一行
  把它拖住了。

机制在 `docs/design/redundant-sorry.md`：内核会把那个洞**删掉**再检查一遍整条声明，
通过就说明它是多余的，于是发一条 `redundant-sorry` 警告，并叫你删掉那一行。
下面两个例子，一个走了警告那条路，一个连警告都没有：

```sokonanoda
axiom A : Prop
axiom B : Prop
axiom f : A → B
theorem t (h : A) : B := f h
 sorry
```

`f h` 已经把 `B` 证出来了，后面那行 `sorry` 没有位置可填 ⇒ 检查通过，但会多一条
`redundant-sorry` 警告，指着那一行叫你删掉。

```sokonanoda
inductive Box (p : Prop) : Prop
ctor Box.mk (h : p) : Box p
end

example : Box True := Box.mk True.intro
  sorry
```

这一段更隐蔽：`Box.mk True.intro` 已经是 `Box True` 的完整证明，末尾那行 `sorry`
同样没有位置可填，可它**连警告都没有** —— 文件照样算一条未完成的练习。所以
**「还是 open」不等于「你还没证出来」**：看到声明没通过时，先检查有没有多余的
`sorry`，再去想证明。

## 常见错误与出路

| 你看到的 | 意思是 | 下一步 |
|---|---|---|
| `` by 块里没有待解目标 `` | `sorry` 写在 `by` 块里，但前面的 tactic 已经把目标关掉了 | 删掉那一行：证明已经完整，它不需要 `sorry` |
| 没有报错、也没有警告，声明却是未完成的 | `sorry` 写在项的位置上，而那个位置不需要它 | 同样先试着删掉那一行，再重新检查；删掉后通过，就说明它是多余的 |

⚠ 上面第二条没有消息可抄：它**不报错、也不发警告**，所以你只能看到「声明未完成」
这个状态。判别方法就是删掉那一行重新检查 —— 真缺口会立刻报「少了东西」，多余的
`sorry` 则直接通过。
