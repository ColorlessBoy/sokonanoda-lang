# rfl

自反：目标是 `=` 或 `↔`，且两边定义相等时成立。

## 怎么用

`rfl` 不带参数，写一行就行。它管的是等号（`=`）和等价（`↔`）这两种目标：
**两边定义相等**时，它直接把目标关掉。

```sokonanoda
example (α : Type) (f : α → α) : f = f := by rfl
```

这里两边都是 `f`，同一个值，显然相等。看起来平凡，但 `rfl` 认的比「长得一样」宽
得多：内核会把两边都算到底，所以 `1 + 1 = 2` 也是它证的。

```sokonanoda
example : (1 + 1) = 2 := by rfl
```

`↔` 的目标同样能交给 `rfl`：

```sokonanoda
example (A : Prop) : A ↔ A := by rfl
```

**边界**：`↔` 只在两边定义相等时能这么用。像 `a ↔ a ∧ True` 这种，两边不定义
相等，`rfl` 会拒绝 —— 这时改用 `constructor` 把它拆成两个方向，各自去证。

## 什么时候用

**适用**：目标是 `=` 或 `↔`，而且你有把握两边算到底是同一个值。证明里凡是「这个
等式其实是定义使然」的地方，第一步都先试 `rfl`，它一步就能收尾。

**不适用**：两边真的需要推理才能相等时。`rfl` 不做任何推理，它只让内核去算；
算不出相等就是不算。`a + b = b + a` 这种要靠归纳证的等式，`rfl` 一定失败。

## 内核在背后判什么

`rfl` 判的是**定义相等**（definitional equality，简称 defeq）。定义相等的意思是：
两边各自按定义展开、按计算归约，最后落到同一个项上。

拿 `(1 + 1) = 2` 说：`+` 是递归定义，内核把 `1 + 1` 归约成 `2`，与右边那个 `2` 对上，
所以相等。拿 `MyP a` 说，`MyP` 是一个 `def`，展开就是 `a`，所以下面这一条也过：

```sokonanoda
def MyP (a : Prop) : Prop := a

example (a : Prop) : MyP a ↔ a := by rfl
```

这条也说明了 `↔` 那一半：`↔` 本身是定义（`Iff A B` 就是 `And (A → B) (B → A)`），
`MyP a` 展开成 `a` 之后两边就是同一个项，于是 `rfl` 成立。反过来，`a ↔ a ∧ True`
的两边展开后仍然不同（左边是 `a`，右边是 `a ∧ True`），内核判不等，`rfl` 就报错。

判定由内核做，`rfl` 只负责造出候选证明项：目标是 `=` 时造 `Eq.refl`，是 `↔` 时造
`Iff.refl`。它只看内核的回答 —— 相等就过，不相等就报错，中间没有别的判断。

## 常见错误与出路

| 你看到的 | 意思是 | 下一步 |
|---|---|---|
| `` `rfl` 需要目标是 `Eq α x y` 或 `Iff A B` 形状（`Iff` 只在两边定义上相等时过）；当前目标是 `True`。目标是 `↔` 时可先 `constructor` 再分别证两个方向 `` | 目标根本不是 `=` 或 `↔`，`rfl` 没有可以判的等式 | 看目标是什么形状：`∧`/`∨` 用 `constructor` 或 `left`/`right`，函数类型用 `intro`，`↔` 先用 `constructor` 拆开 |
| `` `rfl` 判定失败：两边不相等（期望 …，实际 …） `` | 目标是 `=` 或 `↔`，但内核判两边定义不相等 | 两边确实需要推理才能相等 ⇒ 换成别的 tactic 一步步证；`↔` 的目标先 `constructor` 拆成两个方向 |

⚠ **第二条消息读起来有点吓人，这是内核打印方式的问题，不是你的错**：它把整个目标
按内部编码原样印了出来，所以你会在「期望」和「实际」后面看到一长串 `Pi … Sort(0) …`，
以及 `第 N 个绑元（a）` 这样的写法。**`第 N 个绑元` 是在说第几个绑元（bound
variable），`Sort(0)` 是 `Prop` 的内部写法**，那一段是给内核自己看的，不用照着抄。
要读的只有稳定的一段前缀：`两边不相等（期望 …，实际 …）`。这句话告诉你内核把两边
算到了什么，把它与你自己写的两边对一下，就知道差在哪里。
