# ·

聚焦下一个子目标：把缩进块里的 tactic 只作用在它上面；块末未证完则按 Lean 的 `closeUsingOrAdmit` admit 成开放练习。

## 怎么用

`constructor` / `cases` / `apply` 拆出多个子目标之后，每个 `·` 开头一块，
块里只写**当前这个子目标**的证明。下一行要**比 `·` 再缩进**（通常是两个空格）：

```sokonanoda
example (a b : Prop) (ha : a) (hb : b) : a ∧ b := by
  constructor
  · exact ha
  · exact hb
```

一条 `·` 管一块，块里可以写多条 tactic（用换行分隔）：

```sokonanoda
example (a b : Prop) (ha : a) : a ∧ (a → a) := by
  constructor
  · exact ha
  · intro _
    exact ha
```

## 什么时候用

**适用**：目标已经被拆成多个子目标（`constructor`、`cases`、`apply` 的多个前提），
你想按子目标分组、让每一块只看见自己的目标。

**不适用**：只有一个目标、或者想按顺序依次处理所有目标。这时直接写 tactic 就行，
`·` 不是必需的。

## 内核在背后判什么

`·` 自己不判定数学内容；它做两件事：

1. **聚焦**：把当前工作列表里的第一个目标单独交给块里的 tactic；
2. **验收**：块结束时未闭合 ⇒ 按 Lean 的 `closeUsingOrAdmit` 把它 **admit**
   （本语言 = 开放练习，不算错误）；有显式 `sorry` 时洞落在 `sorry`，否则落在
   `·` 自己。块里的 tactic 自己**报错**仍然照常报错（失败不回滚成 admit）。

块里的每条 tactic 仍然走既有判定（`exact` / `apply` / … 各自交内核），
`·` 只是把「这一块属于哪个目标」说清楚。

## 常见错误与出路

- **块没证完**：`·` 里的 tactic 只做了一半 ⇒ 会按 Lean admit 成开放练习；
  想消掉洞就把剩下的 tactic 补进这一块，或者把 `·` 删掉、按顺序写。
- **缩进不够**：`·` 后面那一行必须比 `·` 更深；否则它属于外层块。
- **`·` 写多了**：没有那么多子目标时，多出来的 `·` 会报「没有待解目标」。

## 相关

- `constructor`：按目标取构造子，拆出子目标。
- `cases`：对假设做情形分析，每个分支一个子目标。
- `apply`：用函数的结论对上目标，剩下的前提变成子目标。
